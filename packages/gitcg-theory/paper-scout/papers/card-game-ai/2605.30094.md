## Summary

PokerSkill introduces a **training-free, solver-free framework** that bridges the gap between LLMs and expert poker play. Rather than training an RL agent from scratch (millions of core-hours) or asking LLMs to play poker directly (which fails), PokerSkill uses **human-expert-designed rule-based poker skills** as a structured action-grounding interface. A deterministic context engine analyzes the game state and retrieves only the relevant skill fragments, constraining the LLM's choice to reasonable actions. Against GTOWizard (SOTA GTO benchmark), GPT-5.5 + PokerSkill achieves −57 mbb/hand and Claude Opus 4.6 achieves −80 mbb/hand, reducing losses by 49–61% vs default-prompt baselines.

## Key Contributions

- First demonstration of an LLM achieving competitive performance in a complex imperfect-information game **without game-specific training or solver queries**
- The "skill library + context engine + LLM selector" architecture — the LLM doesn't generate actions, it selects from expert-defined options
- Deterministic context engine filters the skill library to only relevant fragments based on game state
- Rule-based skills alone are weak, LLMs alone are weak, but the combination works

## Connection to Our Work

**Directly applicable to Genius Invokation TCG AI:**

1. **Deck prior / deck evaluation model**: The PokerSkill architecture — expert knowledge encoded as structured rules + LLM as selector — mirrors our approach to deck evaluation. We could build a "GI TCG skill library" (tempo rules, elemental reaction priorities, matchup heuristics) and use our LLM deck prior as the selector.

2. **Training-free deployment**: PokerSkill shows you don't need millions of core-hours of RL training — structured knowledge + LLM reasoning can compete. This validates our strategy of using LLMs for strategic reasoning in GI TCG rather than pure RL.

3. **Skill library design**: The layered skill library designed by human experts is the key innovation. For GI TCG, we could build: (a) opening principles, (b) reaction combo priorities, (c) dice management rules, (d) matchup-specific heuristics.

4. **Context engine**: The deterministic context engine that filters relevant skills per state is analogous to our GBDT ranker's role — narrowing the action space before LLM reasoning.

5. **Imperfect information**: Poker is imperfect-information (hidden cards). GI TCG has hidden dice rolls and opponent hand. The structured interface approach handles this naturally.

## Critical Assessment

- **Strengths**: Clean architecture, training-free, strong empirical results, code available
- **Weaknesses**: Relies on human expert skill design (not learned), skill library is game-specific (transferability unclear), tested only on poker (heads-up NLHE)
- **Reproducibility**: Code at github.com/lbn187/PokerSkill, uses GPT-5.5 and Claude Opus 4.6 APIs
