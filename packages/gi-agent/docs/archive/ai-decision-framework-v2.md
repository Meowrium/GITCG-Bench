## 1. 决策框架总览

```
                    ┌─────────────────────────────────────┐
                    │         战略层 (PlanV2)              │
                    │  全局目标 · 回合优先级 · 风险/变招规则 │
                    └──────────────┬──────────────────────┘
                                   │
                    ┌──────────────▼──────────────────────┐
                    │         战术层 (DecisionShardV1)      │
                    │  作战窗口 · 候选策略 · 退出条件        │
                    └──────────────┬──────────────────────┘
                                   │
                    ┌──────────────▼──────────────────────┐
                    │         操作层 (per-action)           │
                    │  骰子分配 · 伤害计算 · 元素连锁        │
                    └─────────────────────────────────────┘
```

三层递进关系：
- **战略层** 定义"这局要赢的方式"——在换牌阶段确定
- **战术层** 定义"这个时段要完成什么"——每回合开始时刷新
- **操作层** 定义"这步具体怎么做"——每步行动前计算

## 2. 阶段划分

### 2.1 三个阶段

| 阶段 | 回合范围 | 定义特征 | 转换条件 |
|------|----------|----------|----------|
| **开局 (Opening)** | T1 | 建立场上状态（召唤物/支援牌），最小化骰子消耗 | 打出第一个召唤物/支援牌 且 回合结束 |
| **过渡 (Midgame)** | T2 | 利用开局资源发起首次进攻波次，寻求人数优势 | 对方首个角色阵亡 |
| **斩杀 (Closing)** | T3+ | 利用人数/元素优势锁定胜局 | 对方仅剩 1 角色 |

### 2.2 阶段转换触发器

```json
{
  "phase_transitions": [
    {
      "from": "opening",
      "to": "midgame",
      "trigger": "self.summon_active AND investment_cards_played >= 1 AND round >= 2",
      "immediate_action": "switch_to_dps_character"
    },
    {
      "from": "midgame",
      "to": "closing",
      "trigger": "opponent.characters_alive <= 2",
      "immediate_action": "evaluate_freeze_lock_possibility"
    }
  ]
}
```

**关键洞察**：玩家在绫华阵亡的瞬间立即切换到"冻结收尾"思维，而非继续扩散出伤。阶段转换是**离散的、条件触发的**，而非渐进的。

## 3. 决策节点详解

### 3.1 节点 0：换牌评估 (Mulligan)

**输入特征：**
- 己方卡组（角色组合、核心 combo 线路）
- 手牌内容（5 张）
- 先手/后手信息

**条件判断：**

```
IF 手牌包含 <投资型支援牌> （派蒙、桓那兰那等） → KEEP
IF 手牌包含 <过牌> （运筹帷幄等） → KEEP
IF 手牌包含 <后期专属牌> （需高回合数才能触发） → DISCARD
IF 手牌包含 <保命牌> （料理、护盾等） AND 开局角色 <不会站场承伤> → DISCARD
```

**决策逻辑：**
- 换牌不是孤立评估每张牌的价值，而是**先确定开局策略，再按策略匹配手牌**
- 保命牌在"莫娜打 E 就切走"的策略下无价值 → 换掉
- 后期牌在"T1 单动蓄爆"的策略下无法触发 → 换掉

**对应当前 AI 缺陷：** GBDT 打分对每张牌独立评估，缺少"先定策略再选牌"的层次关系。

### 3.2 节点 1：T1 骰子重投 (R1 Reroll)

**输入特征：**
- T1 计划行动序列（如：莫娜 E → 打派蒙）
- 各行动所需骰子类型和数量

**决策逻辑：**

```
骰子分桶算法：
  桶1（技能骰）：莫娜 E 需要 3 水 → 保留水骰
  桶2（蓄爆骰）：派蒙需要 3 同色 → 保留同色骰
  其余骰子 → 重投，目标填充桶1或桶2
```

**核心原则：先规划行动，再匹配骰子。** 骰子没有"绝对好"，只有"对当前计划好"。

### 3.3 节点 2：T1 行动 (R1 Action)

**输入特征：**
- 骰子分配结果
- 手牌中可用投资牌
- 对方出战角色

**决策序列（本局实例）：**

```
Step 1: 莫娜 E（挂水 + 召唤物）
  - 消耗：3 水骰
  - 产出：水召唤物（每回合末挂水），莫娜获得被动速切

Step 2: 打蓄爆牌（派蒙 + 桓那兰那）
  - 消耗：对应骰子
  - 产出：未来回合额外骰子

Step 3: 声明结束
  - 目的：抢先手（利用莫娜被动速切在 T2 第一动扩散）
```

**抢先手判断：**

```
IF 后手方 AND 已完成 <挂元素 + 打蓄爆牌> → 声明结束
  理由：后手方结束 → 下回合先手方先动 → 先手方动完后，后手方利用莫娜被动速切抢第一动
```

### 3.4 节点 3：条件风险评估 (Risk Check)

**输入特征：**
- 对方出战角色状态
- 对方可能的反制动作

**决策逻辑（本局实例）：**

```
风险识别：对方神里绫华如果 <先结束回合> → 可以切走 → 莫娜召唤物挂水失效
风险评估：对方 T1 选择继续行动（打蒙德土豆饼）而非结束 → 风险解除
风险接受条件：IF 对方 <低血量压力> AND <有治疗手牌> → 对方倾向继续操作而非抢先手
```

**通用风险评估维度：**

| 维度 | 权重 | 评估方法 |
|------|------|----------|
| 对方抢先手概率 | 高 | 对方剩余骰子数、对方手牌中快攻牌占比 |
| 对方切人概率 | 中 | 对方是否有速切能力、是否被元素克制 |
| 斩杀线暴露 | 低 | 己方角色血量是否进入对方斩杀线 |

### 3.5 节点 4：T2 过渡期攻击波次 (Midgame Offense)

**输入特征：**
- 己方召唤物状态（水附着目标）
- 对方出战角色元素状态
- 己方 DPS 角色骰子需求

**决策序列（本局实例）：**

```
Step 1: 重投骰子 → 优先找风骰
Step 2: 切流浪者（利用莫娜被动速切 = 快速行动）
Step 3: 流浪者 E（风附魔）
Step 4: 普攻 → 目标选择逻辑：
  - 流浪者 E 后普攻攻击 <对方出战角色的下一个角色>
  - 当前目标 = 宵宫（有水附着）
  - 风打水 → 扩散 → AOE 溅射伤害
```

**扩散目标选择逻辑：**

```
IF 对方出战角色 <有元素护盾/减伤> → 普攻自动转向下一个角色
IF 下一个角色 <有可扩散元素> → 扩散成立 → AOE 全队
```

**伤害计算（操作层精确计算）：**

```
普攻直伤：流浪者 ATK → 宵宫
扩散 AOE：(绫华 1 + 宵宫 1 + 申鹤 1) 点
绫华护盾（莲花酥）：扩散伤害 -3 → 实际 0 伤
总伤害：绫华 0 + 宵宫 1 + 申鹤 1
```

### 3.6 节点 5：斩杀链计算 (Lethal Chain)

**输入特征：**
- 对方每个角色的当前 HP 和元素状态
- 己方可用的充能转移手段（白垩之术）
- 己方角色充能状态

**决策序列（本局实例）：**

```
已知：绫华 HP 9（冰附着），流浪者充能 1/3，莫娜充能 1/3
手牌：白垩之术（转移充能）

计算：
  Step A: 普攻 → 宵宫（有水）→ 扩散 → 绫华承伤 → 绫华 HP 9→7
  Step B: 白垩之术（莫娜充能 1 → 流浪者）
  Step C: 流浪者 Q（3 充能，对绫华）→ 绫华 HP 7→0 ✓ 击杀

骰子预算：
  普攻 3 骰 + 白垩 1 骰 + Q 4 骰 = 8 骰
  剩余 1 骰 → 存入桓那兰那
```

**斩杀链核心原则：**
1. 先计算最终伤害 → 确认足够击杀
2. 倒推每步所需资源和伤害
3. 验证骰子是否足够支持全链
4. 预留 1 骰容错

### 3.7 节点 6：阶段转换 — 冻结锁定 (Phase Transition)

**输入特征：**
- 对方剩余角色及元素附着状态
- 己方剩余角色及可用元素

**决策逻辑（本局实例）：**

```
条件检查：
  ✓ 对方宵宫 HP 5（水附着）
  ✓ 对方申鹤 HP 7（水附着）
  ✓ 己方优菈可用（冰元素）

判断：所有剩余敌方角色均有水附着 → 冻结路线最优

执行：
  T3: 莫娜被动速切优菈 → 优菈 E → 宵宫冻结 → 申鹤冻结
```

**冻结路线触发条件：**

```
IF count(opponent.alive_characters WITH hydro_aura) == count(opponent.alive_characters)
   AND self.has_cryo_character
→ activate_freeze_gameplan
```

### 3.8 节点 7：收尾精确算血 (Final Lethal)

**输入特征：**
- 对方最终角色的 HP
- 己方可用的全部伤害来源

**决策逻辑（本局实例）：**

```
目标：宵宫 2HP（冻结中），申鹤 7HP（水附着）

对宵宫：
  优菈普攻 = 物理伤害 2+ → 击破冻结（碎冰 +2）→ 总伤 ≥ 2 ✓

对申鹤：
  优菈 Q = 冰伤 3 → 触发冻结（+1）→ 3+1=4
  召唤物 = 2 伤
  碎冰 = 2 伤
  总计 = 4 + 2 + 2 = 8 ≥ 7 ✓
```

**收尾算血公式：**

```
总伤害 = Σ(action_damage) + Σ(reaction_bonus) + Σ(summon_damage)
条件：总伤害 ≥ 目标 HP
```

## 4. 资源管理模型

### 4.1 骰子价值：非线性的"匹配度"模型

骰子没有绝对价值。同一枚水骰，在莫娜 E 需要时价值无穷大（缺它技能发不出），在优菈站场时价值趋近零（只可用于无色费用或调和）。**线性系数（如万能=1.2）不成立。**

正确的模型是 **计划匹配度 (Plan Fitness)**：

```
给定回合计划动作序列 A = [A1, A2, ..., An]
每个 Ai 有骰子需求：Require(Ai) = [(type1, count1), (type2, count2), ...]

骰子池 D 的匹配度：
  Fitness(D, A) = min(1, available(D, type_i) / required(A, type_i)) 对所有 type_i

Fitness = 1.0 → 完美匹配，可以执行全部计划
Fitness = 0.5 → 只能执行一半 → 需要调和/降级计划/提前结束
Fitness = 0.0 → 计划完全不可行 → 必须 replan
```

**本局实例：**
- T1 计划：莫娜 E(3水) + 派蒙(3同色)，Fitness 目标 = 1.0
- T2 计划：流浪者 E(3风) + AA(2风+任意)x2，骰子缺口通过重投填补
- T3：优菈冻结路线，Fitness 判断后选择了"普攻收宵宫 → Q收申鹤"的最低骰子消耗链

**关键原则：**
- 骰子价值是 **二元/阶梯函数**，不是线性系数
- 每枚骰子的"价值" = 它对 Fitness(D, A) 的边际贡献
- 缺 1 枚计划骰 → 优先调和 → 调和不可行 → 降级计划（减少动作数）

### 4.2 骰子分桶法 (Dice Bucketing)

```
T 回合开始时：
  1. 列出该回合计划动作序列 [A1, A2, ..., An]
  2. 为每个动作分配骰子桶：Bucket(Ai) = {type, count}
  3. 计算 Fitness(D, A)，若 < 0.7 → 重投/调和填补缺口
  4. 不允许"先看骰子再定计划"——计划驱动骰子，非反向
  5. 剩余骰子 → 存入投资牌 或 提前结束
```

### 4.3 手牌价值：战略和战术层决定的动态权重

手牌没有静态的 S/A/B/C/D 分级。同一张 **白垩之术**：
- 在"需要流浪者 Q 斩杀绫华"的战术场景下 = 核心牌（不可替代，价值极高）
- 在没有充能需求的控制型开局 = 可换掉

手牌价值公式：

```
CardValue(card) = f(strategic_goal, current_phase, tactical_state)

其中：
  strategic_goal: 全局战略（蓄爆→扩散→冻结）
  current_phase: 当前阶段（opening / midgame / closing）
  tactical_state: 当前战术状态（敌方元素附着、己方充能缺口等）
```

**本局实例：**

| 卡牌 | 换牌时价值（战略=蓄爆） | T2 中期价值（战略=斩杀） | 价值变化 |
|------|--------------------------|--------------------------|----------|
| 桓那兰那 | **高**（蓄爆核心） | 低（已打出，不再需要） | 投资型：前置高后置零 |
| 白垩之术 | 中（充能转移，非开局需求） | **极高**（流浪者 Q 缺 2 充能，白垩补 1） | 组合技型：需求时暴涨 |
| 北地烟熏鸡 | 低（莫娜不需保状态） | 低（冻结路线不靠普攻） | 策略排斥型：全程低 |
| 运筹帷幄 | 中（过牌通用价值） | 中（剩余回合少，过牌收益递减） | 窗口衰减型：越晚越低 |

**通用分类（非固定层级，而是价值随时间变化模式）：**

| 价值模式 | 特征 | 换牌时行为 |
|----------|------|------------|
| **投资型** | 前高后零（早打早收益） | 高优保留 |
| **组合技型** | 特定需求时暴涨 | 视战略是否包含该 combo 决定 |
| **策略排斥型** | 当前战略不需要 | 换掉 |
| **窗口衰减型** | 越晚越低 | 取决于手牌位充裕度 |

## 5. 变招机制 (Replan Triggers)

### 5.1 条件触发规则

```json
{
  "replan_triggers": [
    {
      "id": "opponent_early_end",
      "condition": "opponent declared end AND self.has_planned_element_application AND NOT self.element_applied",
      "action": "switch to plan B: direct pressure without reaction setup"
    },
    {
      "id": "core_character_dies",
      "condition": "self.core_character.hp == 0",
      "action": "replan opening window with remaining characters"
    },
    {
      "id": "opponent_core_dies",
      "condition": "opponent.characters_alive <= 2 AND all_opponent_have_hydro",
      "action": "switch to freeze lock gameplan"
    },
    {
      "id": "dice_catastrophe",
      "condition": "count(matching_dice_for_planned_action) < required * 0.5",
      "action": "elemental tuning → replan with reduced budget"
    }
  ]
}
```

### 5.2 变招优先级

```
优先级排序（数字越小越优先）：
  0. 角色阵亡 → 必须立即 reselect + replan
  1. 对方先结束 → 破坏我方元素计划 → 评估是否可接受
  2. 斩杀窗口出现 → 覆盖原计划，优先斩杀
  3. 骰子灾难 → 降级行动或提前结束
  4. 手牌溢出 → 加速消费或调和换骰
```

## 6. 风险模型

### 6.1 风险评估维度

| 维度 | 计算方式 | 阈值 |
|------|----------|------|
| 斩杀暴露度 | 己方角色 HP / 对方最大单次爆发伤害 | < 1.5 → 危险 |
| 元素反制风险 | 对方是否有克制己方出战角色的元素 | binary |
| 抢先手风险 | 对方剩余骰子 / 对方计划行动数 | > 2 → 高 |
| 冻结锁可行性 | 对方存活角色全有水附着 AND 己方有冰角色 | binary |

### 6.2 决策中的风险处理

本局观察到三种风险处理模式：

1. **识别并接受**（T1：对方可能切走避扩散）→ 判断对方行动模式（打治疗 = 不切）→ 继续原计划
2. **主动降险**（T2：绫华有莲花酥护盾）→ 普攻转向无护盾的宵宫
3. **锁定胜局**（T3：冻结路线）→ 对方无解 → 精确算血收尾

## 7. 对当前 AI 框架的改进建议

### 7.1 当前 AI 局限

当前 GBDT 打分模型：读取状态 → 提取特征 → 打分 → 选最高分动作

**缺失的能力：**
1. **层次化规划**：全局战略 → 阶段目标 → 具体动作 的递进关系
2. **条件分叉**：没有"if-then"的分支决策能力
3. **斩杀链计算**：无法规划 2-4 步的精确斩杀序列
4. **骰子分桶**：骰子评估脱离行动计划

### 7.2 建议的改进架构

```
战略层 (PlanV2)：
  - 在换牌阶段由 LLM/规则引擎生成全局计划
  - 定义：全局目标、回合优先级、风险规则、变招触发

战术层 (DecisionShardV1)：
  - 每回合开始/阶段转换时刷新
  - 定义：作战窗口（setup→pivot→burst→exit 节点图）
  - 包含候选策略链和退出条件

操作层 (FragmentResolver + Critic)：
  - 每个 action 从作战窗口当前节点选择最优候选
  - 每步执行后 Critic 验证：是否偏离窗口？是否需要 replan？
```

### 7.3 关键改进点

1. **骰子分桶前置**：在回合开始（而非每步）就规划骰子分配
2. **斩杀链引擎**：独立的 2-4 步序列规划器，计算精确伤害和骰子消耗
3. **条件分叉决策树**：替代线性打分，支持 if-then 分支
4. **阶段转换检测器**：独立模块持续监控触发条件
