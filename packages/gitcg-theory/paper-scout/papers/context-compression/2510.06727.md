## Summary

研究 LLM agent 的 RL 微调用于长程多轮工具使用。上下文长度快速增长成为核心瓶颈。提出 **summarization-based context management**：周期性地用 LLM 生成的 summary 压缩工具使用历史，保留任务相关信息，使 agent 能超越固定 context window 运行。关键创新：**把 summarization 本身作为 RL 优化目标**——推导出 policy gradient 表示，让标准 LLM RL 基础设施同时优化 (a) 工具使用行为 和 (b) 总结策略。实现为 SUPO 算法。

## Key Contributions

- **端到端优化压缩策略**：不是人类设计"该保留什么"，而是 RL 自己学会压缩什么信息
- **Policy gradient for summarization**：数学推导证明 summary 可以作为 policy 的一部分被梯度优化
- **超越固定 context window**：agent 可以在理论上无限长度的交互中运行，不受 token 上限限制
- **交互式函数调用和搜索任务验证**：SUPO 显著提升长程工具使用性能

## Connection to Our Work

- **TurnDigest 的压缩策略优化**：当前 `get_turn_digest_v1` 的字段选择是人工设计的（self_summary / opponent_summary / resource_summary / candidate_actions）。SUPO 说的是「压缩策略本身也要被优化」——Critic 应该额外评估 TurnDigest 的信息充分性。
- **DecisionShard 的滑动窗口**：当前 DecisionShard 有 `turn_range: {start, end}` 和 `exit_conditions`。SUPO 的思路是：shard 结束时不是丢弃它，而是 LLM 生成一个 100 token 的 shard_summary → 滑入下一个 shard 的 context。这就是最简的「滑动窗口 + 摘要」。
- **与 Fragmented Decision 的接口**：`submit_decision_fragment_v1` 的 `local_eval_requests` 可以增加一个 `history_summary_request` 字段，让 LLM 声明「我需要看前面 N 步的摘要来做这个决策」。
- **RL 对齐**：GBRL (2407.08250) 做的是 value model 的 RL。SUPO 提示我们：压缩策略本身也可以是 RL 的目标——GBDT ranker + summary quality 联合优化。

## Critical Assessment

**Strengths**: 端到端训练压缩策略的理论创新；policy gradient 推导扎实；突破固定 context window 的工程价值。  
**Weaknesses**: 需要 RL 训练基础设施（我们的 GBDT pipeline 目前不支持 LLM 端的梯度）；只验证了函数调用和搜索任务，卡牌游戏待确认。  
**Reproducibility**: 需要 RL 训练环境，不是纯 inference-time 方案。
