# 强耦合与构筑论的失效

## 现象

在七圣召唤中，几乎所有参数都与对手行为、整局游戏、甚至 meta 环境耦合，无法孤立求解。玩家社群的"构筑论"——选定某张牌/技能作为标准模型，然后用折算数值衡量其他卡牌——几乎完全失效。

## 强耦合的起源：单回合内的频繁交互

强耦合确实从**单回合内**就开始了，但原因不只是"交互频繁"，而是交互的结构性质：

### 1. 行动是离散且交替的

与"同时结算"的游戏不同，七圣召唤是**严格交替行动**。每个行动后对手可以选择响应或不响应。这意味着：

- 你打出 E 技能后，对手在看到你的行动后决定是响应（反击）还是跳过（让步）
- 你的"最优行动"取决于对手的响应策略，而对手的响应策略取决于你的行动
- 这是一个**嵌套的博弈树**，不是线性方程

每多一次交互，博弈树的深度+1，分支因子×（对手响应选项数）。单回合内一次简单的"你放技能→对手切人"交互就已经是一层 min-max 了。
在打木桩时，即使是1伤普攻的技能模组（法师、克洛琳德），每回合只进行2次普通攻击，打满15回合（游戏回合数上限）也能打出30点伤害。而在PVP实战中，回复、减伤、强制切人、冻结、石化等等交互都会使得这个理想情况出现巨大偏差。

### 2. 元素附着是公共状态

元素附着同时影响攻守双方：
- 你给自己挂的水可以被对手用来打蒸发（你帮对手增伤了），也可以后手消掉身上的元素附着
- 对手挂的元素可以切人躲掉
- 具体的反应情况不仅取决于技能，还取决于双方的**相对行动顺序**、站位和出战角色（变化），而这是博弈的结果

元素附着让"伤害"这个看似属于攻击方的参数，实际上由**双方共同决定**。你无法孤立地按打木桩的情况说"这一套技能下来打 3+5点伤害"——它可能是 3+5（反应），可能是 3+3（躲反应或消元素）。

### 3. 充能是跨回合的累积状态

充能不能被单回合独立评估。角色 A 的 Q 技能在第 5 回合释放，其"真实成本"是前 4 回合为蓄充能所做的所有行动的**机会成本之和**。而这些前序行动的选择，又取决于前 4 回合对手做了什么。

所以：**一个技能的收益 = f(整局游戏状态) = f(对手所有历史行动 + 随机性)**

这就是为什么折算失效——你找不到一个稳定的"基准"。

## 为什么构筑论失效

构筑论的核心假设：

```
存在一个标准模型 M，使得任意卡牌 X 的价值 ≈ X 相对于 M 的折算值
```

这个假设要求：
1. M 的价值在不同对局中相对稳定 → ❌ 不成立（对手不同，M 的实际价值剧烈波动）
2. X 相对于 M 的关系在不同对局中保持单调 → ❌ 不成立（某些牌在特定对局中从"废牌"变成"关键牌"）
3. 折算是可传递的：如果 A > B 且 B > C，则 A > C → ❌ 不成立（非传递性博弈）

七圣召唤满足**非传递性博弈**的条件：牌组 A 克制 B，B 克制 C，C 克制 A。在这种环境下，线性排序本身就不存在。

## 能否列出问题对应的所有相关参数？

对于有限的环境和对局，理论上可以。但需要面对一个挑战：

### 朴素方法：枚举所有依赖

```typescript
interface QuestionContext {
  // 直接参数
  myDeck: Deck;
  opponentDeck: Deck;
  gameState: GameState;

  // 派生参数
  elementExposure: ElementMap;       // 当前场上元素附着
  energyState: EnergyState;           // 双方所有角色充能
  diceAvailability: DiceCount;        // 当前骰子
  handComposition: Card[];            // 手牌

  // 历史参数
  actionHistory: Action[];            // 已执行的行动序列
  reactionHistory: Reaction[];        // 已触发的反应记录
  cardUsageHistory: CardPlay[];       // 已使用过的卡牌

  // Meta 参数
  opponentResponseModel: Strategy;    // 对手的响应策略估计
  metaDistribution: DeckFrequency[];  // 当前 meta 中牌组出现频率
}
```

**问题**：参数空间虽然有限，但维度极高。133 角色 × 数百卡牌 × 元素状态 × 充能状态 × 骰子状态 × 手牌状态……组合数爆炸。

### 可行的方法：分层参数依赖图

不做全枚举，而是构建参数依赖图，**按问题类型只展开相关子图**：

```
"这张牌值不值得带？"
  ├── 直接：这张牌的效果是什么？费用多少？
  ├── 一阶依赖：我的牌组里谁能触发这张牌的条件？手牌循环能多大概率抽到？
  ├── 二阶依赖：对手的牌组里有多少牌会削弱这张牌的效果？当前 meta 有多少这类对手？
  ├── 三阶依赖：带了这张牌后，我的牌组整体节奏如何变化？与不带时的 DPT 差多少？
  └── 终止条件：当展开深度超过可计算范围时，标记为"需模拟验证"
```

这本质上是**按需展开的参数依赖树**，而不是预先列出所有参数。

## 放宽输出类型：从标量到矢量

### 标量失效的根本原因

一个标量（如"这张牌值 7 分"）隐含了**全序关系**（A=7 > B=5）。但在非传递性博弈中，全序不存在。

### 矢量化的思路

将评估从标量升级为**多维矢量**，每个维度对应一个"对手/场景假设"：

```typescript
// 不再是: cardValue: number
// 而是:
type CardValueVector = {
  vsAggro: number;      // 对快攻牌组的表现
  vsControl: number;    // 对控制牌组的表现
  vsMidrange: number;   // 对中速牌组的表现
  vsMetaX: number;      // 对当前 meta 第 X 流行牌组的表现
  // ...
};
```

**优点**：保留了"在某些情境下强、某些下弱"的信息，不强制全序。

**缺点**：维度选择本身是主观的。选哪些对手/场景作为维度？维度太多则无法比较，太少则丢失信息。

### 更进一步：区间值

```
cardValue = [low, high]  // 在不同对局中的价值分布区间
```

区间窄 = 价值稳定，适合作为构筑核心
区间宽 = 价值波动大，适合作为针对卡或看 meta

区间有重叠的两张牌 → **不可比较**，这是诚实的结果，而不是强行排序。

### 更进一步：帕累托前沿

对于一组卡牌，计算每个维度的得分，然后找帕累托最优集——这些牌中没有任何一张在所有维度上都劣于另一张。

```
牌 A: (快攻8, 控制3, 中速6)
牌 B: (快攻5, 控制7, 中速5)
牌 C: (快攻4, 控制4, 中速4)
→ A 和 B 都在帕累托前沿上，C 被 A 和 B 同时支配
→ 结论：带 A 还是 B 取决于 meta 倾向，但不应该带 C
```

**这比标量排序诚实得多，且不需要知道"绝对正确答案"。**

## 放弃折算后，我们还能讨论什么？

折算的本质是："以 X 为基准，Y 等于多少个 X"。放弃这个框架后，可讨论的替代框架：

### 1. 阈值讨论

不问"这张牌值多少"，而问"这张牌是否满足某个最低要求"：

- "这张牌能否在我方主 C 蓄力期提供足够的场面压力？" → 能/不能
- "这张牌能否在对局结束前（约 10 回合）创造足够的价值？" → 能/不能

阈值讨论的好处是**不需要精确折算**，只需要回答"够不够"这个二元问题。

### 2. 角色讨论

不问"这张牌值多少"，而问"这张牌在牌组中扮演什么角色"：

- 过渡卡：帮助度过弱势期
- 致胜卡：创造无法被规避的威胁
- 针对卡：克制特定 meta 中的主流牌组
- 灵活卡：在多种场景下都有用，但不突出

两张不同角色的牌不需要比较数值——它们不是竞争关系，而是**互补关系**。你不需要比较"刀和盾哪个更强"。

### 3. 组合效应讨论

不孤立评估单张牌，而是评估**牌组作为整体的行为模式**：

- "这套牌组的典型对局是什么样的？"（叙事描述，而非数值）
- "它在什么条件下赢？什么条件下输？"（条件枚举）
- "它的核心战术是什么？对手要阻止什么就能击败它？"（攻防分析）

### 4. 信息论视角

将每张牌视为对**信息空间**的贡献：

- 这张牌缩小了多少不确定性？（例如：对手看到你打出某张牌后，对你牌组的推断改变了多少）
- 这张牌增加了多少自己的不确定性？（例如：随机效果牌）
- 这张牌在信息博弈中是"信号"还是"噪音"？

### 5. 稳健性而非最优性

不问"什么牌最强"，而问"什么牌最不容易被打烂"：

- 这张牌在对手做最优应对时，保底收益是多少？
- 这张牌的收益方差有多大？

这接近**极小化极大（minimax）**思维：选择在最坏情况下仍然可接受的牌，而不是在理想情况下最强的牌。

## 开放问题

1. **计算复杂度**：帕累托前沿的维度每增加一个对手类型，计算量指数增长。对于 133 角色 × 数百卡牌的构筑空间，帕累托分析是否实际可行？

2. **Meta 漂移**：矢量评估的维度（对手类型分布）随 meta 变化。是否需要设计一个"meta-agnostic"的评估框架？还是说接受"每个 meta 下答案不同"本身就是正确的？

3. **人类认知适配**：标量排序虽然不精确，但人类容易理解和使用。矢量和帕累托前沿对人类来说认知负担很重。如何将高维评估结果压缩回人类可理解的形式？或者说，七圣召唤的构筑讨论注定无法被简化——这才是为什么"构筑论"失效的根本原因？

4. **与 AI 搜索的桥接**：如果人类用"角色/阈值/组合效应"讨论构筑，AI 用 beam search 搜索行动序列，两者之间能否建立有效的沟通接口？AI 的搜索结果能否被翻译回人类可理解的战略叙事？
