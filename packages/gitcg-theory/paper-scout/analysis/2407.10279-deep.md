# [2407.10279] AlphaDou: End-to-End Doudizhu AI — Deep Analysis

**Date**: 2026-05-25 | **Analyst**: Paper Scout Deep Analysis Agent
**Paper**: 2024-07-14 (updated 2024-09-13), 2 authors (Chang Lei, Huan Lei)

---

## 一句话总结

AlphaDou 将斗地主的叫牌（bidding）和出牌（cardplay）统一到一个端到端框架中，用**双头 Deep MC（胜率 + 期望值）** 做动作剪枝——这与当前 GI TCG 需要在 deck 选择和 round-by-round 决策间割裂处理的问题有结构性对应。

## 核心贡献

1. **统一 Bidding + Cardplay**：斗地主有两个自然阶段——叫牌（是否做地主的离散决策）和出牌（序列决策）。之前的 DouZero 为简化环境砍掉了叫牌阶段。AlphaDou 将两者统一在一个双头网络中：一个头预测胜率，一个头预测期望值（炸弹翻倍等）。**这与 GI TCG 的 deck selection（离散选择）→ 回合决策（序列决策）有结构性同构**。

2. **期望值引导的动作空间剪枝**：动作空间从完整的合法动作集减少到"期望值为正"的子集——不是硬剪枝（排除动作），而是用期望值对未来可能的翻倍/炸弹做预判。在 GI TCG 中对应：我们可以在 MCTS 展开前用 value model 或 GBDT ranker 的 score 阈值做动作过滤，减少分支因子。

3. **Deep MC 的实际变体设计**：AlphaDou 并非纯粹复制 DouZero 的 Deep MC——它在输出层同时产生 policy（action distribution）和 value（win rate），且 value 用于在推理时做 top-k 动作剪枝。这种"双头 + 推理时剪枝"的模式对 GI TCG 的 MCTS + GBDT 架构有直接借鉴价值。

## 与我们工作的交集

### 直接影响？
- **DUAL-HEAD ARCHITECTURE FOR CGT**：AlphaDou 的双头（胜率 + 期望值）直接映射到 CGT 的 dual evaluation 需求——我们需要同时知道"这个决策的胜率是多少"和"这个决策会导向什么类型的子游戏（Number/Non-number？）"。一个头预测博弈值（game-theoretic value），另一个头预测子游戏的不确定性（temperature / cold-hot classification）。
- **Deck selection ↔ Bidding analogy**：GI TCG 的 deck selection 和斗地主的叫牌都是"游戏开始前的离散高杠杆决策"。AlphaDou 的统一训练方式（bidding 和 cardplay 共享 backbone）提示我们应该考虑将 deck 选择也纳入 RL 训练循环，而非靠外部预定义的"deck tier list"。

### 方法论借鉴？
- **Action pruning by value**：AlphaDou 用 learned value function 在推理时过滤动作（而非仅在训练时用）。这与我们的 GBDT value model 用法不同——我们目前用 value model 做叶子节点评估，但可以考虑在 MCTS 展开前就用 ranker score 做 top-k 过滤，减少搜索宽度。
- **Real environment training**：AlphaDou 特意强调在真实斗地主规则下训练（而非简化版）。这对 GI TCG 是一个提醒——我们的 self-play 环境应该尽可能接近 real game（包括完整的结算顺序、OHM query 系统等），因为简化可能导致 agent 在真实对局中暴露盲点。
- **2 人小团队可行性**：AlphaDou 只有 2 位作者，展示了在已有框架（DMC）上进行架构创新的可行性——不需要大团队也能做出 SOTA。这对 GI TCG（同样是小团队）是一个激励性信号。

### 不相关之处？
- **斗地主特有的叫牌机制**——"叫地主"的机制（按叫分顺序、炸弹翻倍、春天）是游戏特有的，直接架构成 GI TCG 的 deck 选择需要大幅改编。
- **Deep MC vs MCTS**——AlphaDou 用的是无搜索的 Deep MC（Monte Carlo rollout 端到端），而我们用的是有搜索的 MCTS。这是根本性的算法差异，不能简单替代。
- **1v2 合作/竞争混合**——斗地主的 1v2 动态（地主 vs 农民）和 GI TCG 的 1v1 完全不同。合作推理（两个农民协同出牌）在 GI TCG 中没有对应。

## 可落地动作（≤3 条）

### 1. 原型：将 GBDT value model 用于 MCTS 动作剪枝
**具体做法**：
- 在 `packages/gi-agent/src/mcts/mcts.ts` 的 expansion 阶段（`generateChildren` 附近），增加可选的 top-k 过滤：
  - 对当前状态的所有合法动作调用 GBDT value model 做一个 one-step-lookahead
  - 保留 value 最高的 k 个动作（k=10-20），其余不进入搜索树
- 这类似于 AlphaDou 的 inference-time action pruning，但在 MCTS 框架内
- 实验：`packages/gi-agent/src/evaluation/branch-eval/`，对比 `k=10/20/unlimited` 下的搜索效率（wall-clock time vs win rate）
- 配置参数：`mctsActionPruning?: { k: number, minPriorThreshold?: number }`

### 2. 分析：Dual-head GBDT（rank score + game type）
**具体做法**：
- 当前 GBDT ranker 输出 scalar score。考虑修改 `slot_linear.py` 增加第二个输出头：`game_type: float`（Number-guarantee score：给定当前状态下，游戏有多大概率是可以被 CGT 分类为 Number 位置）。
- 训练信号：从 replay 中学习——当终局胜率明确且对局轨迹简单时标注为 high Number-probability；当终局存在逆转（早期劣势但后期翻盘）时标注为 low Number-probability。
- 在推理时结合两个头：game_type 决定 branch factor（高 Number → 浅 MCTS，低 Number → 深 MCTS），对应 P2 的 skipMctsWhenCold。

### 3. 研究：将 Deck Selection 纳入 Self-Play 训练循环
**具体做法**：
- 当前 self-play 的 deck 对局是预设（10 副卡组的固定对阵）。AlphaDou 的 bidding 训练提示我们可以让 agent 在训练中同时学习 deck 选择和 round 策略。
- 技术路径：在 self-play 环境中增加 "pre-game deck selection" 阶段，agent 根据对手已知信息（或 hand probability prior）选择卡组。
- 但注意：这需要大幅扩展训练环境（当前 `run-self-play.ts` 假设固定 deck）。先做 feasibility assessment（1 页 doc），不确定是立即实施。

## 风险与质疑

| 风险维度 | 评估 |
|---------|------|
| **实验规模** | ⚠️ 斗地主虽然是复杂卡牌游戏，但**状态空间远小于 GI TCG**（54 张牌 + 3 玩家 vs 1000+ 状态特征 + 复杂的结算链）。AlphaDou 在斗地主上的 SOTA 不保证方法论能 scale 到 GI TCG 的复杂度。 |
| **宣称是否过度** | 🟡 "SOTA among public Doudizhu models" 的声称可接受——在斗地主领域这是真实的。但"End-to-End"和"Unified"在 GI TCG 语境下需要 cautiousting：斗地主的叫牌只有几轮，而 GI TCG 的 deck 选择涉及 ~60 张卡 × ~30 角色的组合，搜索空间天差地别。 |
| **代码不可复现** | 🔴 只有 2 位作者且未发布代码。方法论描述较为详细（网络结构、训练超参数），但复现需要大量工程。这对于"2 周内快速验证"的目标是显著的障碍。|
| **与 MCTS 的关系** | 🟡 AlphaDou 用的是无搜索 DMC，而我们有 MCTS。将 AlphaDou 的双头剪枝直接移植到 MCTS 框架中需要 adaptation work——DMC 的剪枝发生在 rollout 前，MCTS 的剪枝需要与 PUCT 公式中的 prior 项协调（剪得太激进会抵消 exploration）。 |
| **CGT 连接** | 🟢 期望值头（expectation head）与 CGT 的"combinatorial value with temperature"有直觉上的联系。斗地主的炸弹翻倍等于"增加游戏的热度"——CGT 中的 temperature 概念恰好捕捉了这种"一个 action 可能导向 different outcome value 的程度"。如果我们将 AlphaDou 的期望值头重新解释为 CGT temperature estimator，两条线就有了理论统一。|

## 推荐优先级：📅 下周（Methodology reference）

**理由**：AlphaDou 是值得深入阅读的方法论文，但它的具体算法（DMC + dual-head）不能直接替代我们的 MCTS + GBDT 架构。最大的价值在于**架构设计模式**（端到端统一、双头输出 → 推理时剪枝）和**斗地主 → GI TCG 的类比映射**（叫牌 ↔ deck selection）。MCTS 动作剪枝的原型值得做，但排在本周的 CWM 原型和评估协议升级之后。

**后续跟踪**：不需要跟踪这篇 paper 本身（2 人 2024 paper，引用量较低）。需要跟踪的是 "DMC dual-head architecture" 模式在其他卡牌游戏 AI 中的应用（如 Mahjong、Bridge），积累"双头什么时候有用"的证据。
