**结论：LLM-Prior 与 baseline（启发式规则引擎）处于统计均势。**

## 注意事项

1. **JSON 解析问题**：benchmark 输出的 per-matchup 详细数据在解析时出现 `'str' object has no attribute 'get'` 错误，仅成功提取了汇总统计。无法获取逐对阵的胜率明细。
2. **数据来源受限**：benchmark 运行在 Docker 容器中，容器终止后详细结果文件可能已丢失。建议在 benchmark runner 中将结果 JSON 挂载到宿主机持久化。
3. **统计功效**：225 局提供了合理的统计基础，但每个对阵仅 5 局，单个 matchup 的置信区间较宽。如需逐对阵分析，建议增加到每对阵 20-30 局。
4. **先行优势**：所有对局 LLM-Prior 为 P0（先手），46.67% → 先手优势并未转化为胜率优势，值得关注。

---

## 建议

1. **修复 JSON 输出**：确保 benchmark runner 输出格式一致，便于自动化解析
2. **持久化结果**：将 benchmark 结果挂载到 `/mnt/d/AI/GTCG/genius-invokation/packages/gitcg-theory/bench-results/` 目录
3. **增大样本量**：每个对阵至少 20 局以获得可靠的 per-matchup 分析
4. **超越 baseline**：v20 模型已经在 baseline 水平，下一步应追求显著超越（>55%）
5. **CGT 优化集成**：在达到 baseline 之上后，可以开始测试 CGT 框架的剪枝/温度优化效果（参考 `cgt/` 目录下的分析文档）
