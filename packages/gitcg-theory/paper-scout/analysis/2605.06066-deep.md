# [2605.06066] Causal RL for Complex Card Games: A MTG Benchmark — Deep Analysis

**Paper**: 2026-05-07, U. Western Australia, 0 citations (brand new)

## 一句话总结

第一个将因果 RL、隐藏信息和大规模 masked action space 统一到卡牌游戏 benchmark 的工作——用 MTG 的 Structural Causal Model (SCM) 揭示了**纯胜率指标掩盖的诊断结构**：CGFA-PPO 在胜率上与 masked PPO 持平，但在因子级校准和跨 archetype 迁移上展现出因果归因优势。

## 核心贡献

1. **因果 RL × 复杂卡牌游戏的首次系统对接**：不是简单的"用 RL 打 MTG"，而是建立 MTG 的 SCM（生命值/法术力/手牌/场面优势 → 胜率），然后迫使 agent 学习因果结构的内部表征。这在方法论上超越了 DouZero/AlphaDou 等纯黑盒 RL。

2. **分层评估协议（Gold standard）**：
   - Pair 种子控制 + Bootstrap CI（消除噪音）
   - Holm-Bonferroni 多重比较校正（p-hacking 防护）
   - Per-factor calibration trajectory（诊断 agent 学到了什么）
   - Cross-archetype transfer gap（跨卡组泛化能力）
   这些评估方法是我们在 GI TCG agent 评估中**极度缺失的**。

3. **因子对齐 Critic 架构 (CGFA-PPO)**：将 SCM 中胜率的因果父节点映射为 critic 的对齐目标——代理学习的不再是黑盒价值函数，而是可解释的因子级预测器。这与我们的 GBDT ranker 有架构上的相似性（slot-linear features），但 CGFA 的因果对齐是我们的 ranker 完全不具备的。

## 与我们工作的交集

### 直接影响？
- **EVALUATION PROTOCOL DIRECT ADOPTION**：这个 paper 对 GI TCG 最大价值**不是算法本身**，而是评估方法论。当前我们的 benchmark（`gi-agent/src/evaluation/benchmark/cli/run-benchmark.ts`）只报告胜率——这正是 paper 批判的"scalar-only evaluation"。立即采纳配对 seed + bootstrap CI + Holm-Bonferroni 协议。
- **SCM for GI TCG → CGT bridge**：论文的 SCM 方法论可以直接迁移到 GI TCG。建立 GI TCG 的因果图：骰子质量、手牌质量、场面优势（血量差/能量差/召唤物差）、先手优势 → 胜率。这个因果结构与 CGT 的冷热分析（temperature）和 Number/Non-number 分类有天然映射关系。

### 方法论借鉴？
- **Causal credit assignment for deck evaluation**：当前我们用胜率评估卡组强度。但 SCM 可以回答更细粒度的问题：一副卡组是因为"强开局"还是"强后期"获胜？LLM deck prior 应该区分"这副卡组在哪些因果路径上占优"，而不是生成笼统的强弱描述。
- **Factor-level interpretability of GBDT ranker**：当前 ranker 是 slot-linear 特征 + GBDT，输出一个 scalar score。SCM 方法论提示我们应该要求 ranker 输出因子级分数（how much of this score comes from HP advantage vs tempo advantage vs dice quality？），这与我们的 slot 设计（每个 slot 对应一类特征）在理念上一致但缺乏因果对齐。
- **Cross-deck transfer as causal test**：论文的跨 archetype 迁移实验直接映射到我们的跨卡组泛化问题。如果 SCM 因子是正确的，那么 agent 应该能在未见过的卡组上保持因子级校准（即使胜率下降）。

### 不相关之处？
- **CGFA-PPO 算法本身**——我们用的是 MCTS + GBDT ranker + value model，而非 PPO。CGFA 的因果结构可以注入 ranker 但不需要换成 PPO。
- **MTG 特有的 SCM 变量**——法力值（mana）、咒语费用等是 MTG 特有的，需要重新设计 GI TCG 的因果图。
- **Gymnasium 环境**——MTG-Causal-RL 是一个现成 benchmark，但我们不会用它来训练 GI TCG agent。它的价值在于方法论和评估协议。

## 可落地动作（≤3 条）

### 1. 立即可落：采纳统计评估协议
**具体做法**：
- 修改 `packages/gi-agent/src/evaluation/benchmark/cli/run-benchmark.ts`，加入：
  - `--paired-seeds`：固定 N 组种子（如 N=5），每组在同一对局下交换先手
  - `--bootstrap-ci`：对 N 组胜率做 10 万次 bootstrap，输出 95% CI
  - `--holm-bonferroni`：多卡组比较时做多重检验校正
- 为 `packages/gi-agent/src/evaluation/branch-eval/cli/run-branch-eval.ts` 增加 per-factor 分析（按回合拆分胜率、按卡组类型拆分、按骰子质量拆分）
- 输出格式：Markdown 表格 + CI band 可视化

### 2. 本周落地：设计 GI TCG 的 SCM
**具体做法**：
- 撰写 `docs/theory/causal-model-gi-tcg.md`，定义 GI TCG 的因果图
- 候选因果因子（参考 MTG SCM 的映射）：
  - **手牌质量** → 胜率（手牌中可用卡的数量/强度）
  - **骰子质量** → 胜率（当前 dice count 和 element match）
  - **血量优势** → 胜率（角色 HP 差值加权和）
  - **场面优势** → 胜率（召唤物/支援/装备的 board presence）
  - **先手优势** → 胜率
- 分析这些因子与 CGT 的 cold/hot/Number-classification 的关系
- 用 replay 数据做初步的相关性分析（Spearman's ρ）

### 3. 下周落地：Factor-level GBDT interpretability
**具体做法**：
- 当前 GBDT ranker（`gi-ml/python/gitcg_ml/slot_linear.py`）输出 scalar，增加因子分解模块：
  - 通过 Shapley 值将 scalar 分解为各 slot 组的贡献
  - 或者训练 factor-specific 子模型，在推理时组合
- 目标：给定一个状态，不止输出"这个动作的 score 是 0.73"，还输出"其中 0.38 来自血量优势，0.22 来自 tempo，0.13 来自手牌质量"
- 验证方式：检查因子级分数在跨卡组场景下是否保持稳定（covariate shift resistance）

## 风险与质疑

| 风险维度 | 评估 |
|---------|------|
| **实验规模** | ⚠️ CGFA-PPO 仅在 MTG 子集上测试，并非完整 MTG。action space 478（远小于真实 MTG 的万级），state dim 3077（GI TCG 的实际特征维度约 500-1000，但我们有更复杂的规则交互）。规模合适但不代表能直接推广。 |
| **宣称是否过度** | 🔴 **核心风险：CGFA-PPO 在胜率上并未超越 baseline（masked PPO）**。论文的最大声明是"因果结构+因子对齐 critic 有助于解释性和跨 archetype 迁移"，但 baseline agent 的胜率没有提升。如果因果结构不能带来胜率增益，它的实用价值取决于"可解释性"是否是真实需求——在 GI TCG 中，这个需求是真实的（我们需要理解为什么一副卡组强/弱）。 |
| **SCM 是手动的** | 🔴 因果图是 domain expert 手工指定的，没有自动化发现。如果我们的 GI TCG 因果图错了一个重要的因子（如"元素反应链"可能是一个关键的因果中介变量），所有基于此 SCM 的分析都会有偏差。 |
| **SCM ≠ causal inference** | ⚠️ 论文的名称是"causal RL"，但实际是"SCM-informed RL"——因果图用于辅助 critic 设计，并非真正的因果推断（如反事实推理）。这降低了方法论在 CGT 反事实分析中的直接适用性。 |
| **与 CGT 的关系** | 🟢 SCM 中的"因果因子"和 CGT 中的"option/dominated option"有深层联系。CGT 的 Number 值本质上是一种因果摘要（给定当前状态+合法选项，可以精确计算博弈值）。如果我们成功建立 GI TCG 的 SCM，CGT 的 Number/Non-number 分类可以表述为：Number 位置 = 因果图中所有因子都是可分离且确定的；Non-number 位置 = 存在相互依赖或概率性的因果路径。 |
