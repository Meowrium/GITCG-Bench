## 1. 设计原则：同一坐标系上的两条边界

层级坐标系不需新造——answer20260728 §2.1 的扰动不变量检验已按信息域定义了层级，§1.5 已标注各层的理论可达性。测试设计 = 在同一坐标系上画两条边界：

- **理论边界**：哪一层原则上不可能从静态信息推出（L2 动态项需模拟、L3 需对局展开、L4 需环境统计——§1.5 推导链第 3–5 步）；
- **实测边界**：LLM 实际做到哪一层。

**gap 判读规则**：

| 实测 vs 理论 | 含义 | 处置 |
|---|---|---|
| 实测低于理论 | 能力缺口 | 可改进方向（提示、工具、训练） |
| 实测 = 理论 | 正常 | 记录 |
| 实测高于理论 | 可疑——记忆泄漏或题目伪相关 | 必须用虚构数据复核（§3.2）；L4 层"答对"几乎一定是背了 meta 而非做了分析 |

## 2. 层级划分

### 2.1 主轴：信息域（沿用 answer20260728 §2.1，卡组内秉层按推理深度细分）

| 层级 | 扰动判据 | 内容 | 理论可达性 | 金标准来源 |
|---|---|---|---|---|
| L0 规则/单卡语义 | 只读规则文本可答 | 费用、效果、目标合法性 | 静态可答 | `packages/data/src` 解析 |
| L1 卡组内秉·静态 | 对手任意替换答案不变 | 元素构成、费用曲线、共鸣资格、可枚举技能链/反应兼容 | 静态可答 | deck code 解析 |
| L2 卡组内秉·动态 | 同上，但需执行 | 骰子可行性、真实行动序列、充能时序、斩杀窗口 | 需状态机/蒙特卡洛/搜索（§2.1 终止条件三项） | 引擎模拟/搜索 |
| L3 对局 | 答案随具体对手改变 | 威胁-应对映射、roleShift、窗口变形 | 需对局展开 | self-play 统计 + matchups 标注 |
| L4 meta | 答案随对手**分布**改变 | 针对牌取舍、帕累托前沿 | 范畴性不可能（§1.5 第 5 步） | 给定 π（固定对手池）下的环境统计 |

L2 是最有诊断价值的一层：它精确落在理论边界上——引擎可算出精确金标准，纯 LLM 只能近似。

### 2.2 横轴一：阶段

- **赛前**（预测任务）：卡组分析、matchup 预测、调度/mulligan 方案；
- **赛中**（实战决策）：见 §3.6；
- **赛后**（元反思本体）：归因、反事实推理、从少量样本更新信念，见 §3.5、§3.7。

### 2.3 横轴二：信息/工具条件（消融变量，不是层级）

- 信息：rules-only / +卡牌数据 / +N 局 replay；
- 工具：纯 LLM / +查询 DSL / +引擎模拟。

产出形态 = 层级 × 工具的二维能力地图，而非单一线性结论。

## 3. 测试方法

### 3.1 引擎即 oracle

引擎是规则的可执行规范，天然的金标准生成器。各层金标准来源见 §2.1 表：L0/L1 静态解析，L2 蒙特卡洛/搜索，L3 self-play 统计与 matchups 标注，L4 给定 π 下的环境统计。

### 3.2 反记忆控制（LLM 评测特有、不可省）

LLM 预训练可能见过真实卡牌与 meta。用 `packages/custom-data-loader` 构造**虚构卡牌/变体规则**重测关键题目，把"推理"从"回忆"中分离。真实数据上的高分不能作为能力证据，除非在虚构数据上同层级复现。具体构造方案见附录 A。

### 3.3 扰动不变量探针（直接复用 §2.1）

同一问题在对手替换下重问：L1/L2 答案应**不变**、L3 答案应**变**。测的不只是对错，而是**作用域校准**——最常见的失败模式是把 L1 知识越界外推到 L3。记"作用域违规率"为独立指标。

### 3.4 边界自知（元认知）

让 LLM 先判定问题层级再给置信度。参照 §2.1 程序，正确行为是在 L2 动态项标"需模拟验证"、在 L4 标"需环境统计"。**能说出"这题需要数据/模拟"本身就是被测能力**；在不可能层硬答且置信不低，记为校准失败。

### 3.5 少量数据使用效率

给 N 局 replay/mutation log，测三点：

- (a) 能否提取正确的聚合统计（对引擎全量统计核对）；
- (b) 是否对小样本过度外推——n=3 的胜率该不该动先验，期望答案是带不确定度的弱更新；
- (c) 归因能否过 answer20260728 §1.4 三判据：指认到具体 mutation 链（可追溯）、提出可干预的机制假设（干预开关）、不把噪声当机制（无残差意识）。

### 3.6 赛中评测

- 合法行动率（硬门槛）；
- 对固定 baseline（random / 启发式 / 固定模拟数 MCTS）的胜率；
- blunder rate：以 MCTS action-value 差衡量单步损失；
- 利用种子化 LCG 做确定性对照（同 seed 可复现、先后手交替平衡）；统计纪律沿用 answer20260728 §4.2（±1pp 需 n=2500，先小样本筛大效应再复核）。

### 3.7 赛后归因的反事实评分

给 replay + 结果，让 LLM 指认转折点与胜负原因；金标准 = 引擎反事实——从被指认的决策点换动作重跑，以估值差验证归因是否成立。种子化回放使这种反事实**精确可算**，这是本仓库做此评测的独特优势。

## 附录 A：§3.2 反记忆控制的虚构卡组构造方案

> 目标：构造虚构卡组 F，使 P（该卡组出现在预训练语料）≈ 0，同时满足两条硬约束——①引擎可执行，金标准（L0–L2 解析、L2 模拟）照常可算；②与真实母版卡组**难度配对**，使"真实高分、虚构低分"的差值可归因于记忆而非题目变难。

### A.1 母版选择

以 `packages/benchmark/deck-analysis/data/ground-truth/v6.3.0/decks/` 的 9 套标注卡组（水八等）为母版池：它们已有 deckProfile / keyCards / openingSequences 标注，可直接复用为真实组评分参照；均为真实 meta 卡组，预训练暴露度高，正是需要对照的一端。N 臂（A.2）以 cutoff 后版本的实装卡组为材料，当前可用 `ground-truth/v6.6/` 起步（仅 1 套标注，需扩充）；`@gi-tcg/data` 实装至 v6.6（`old_versions/` 最新 v6.5.0），引擎支持自选版本开局，新旧版本对照无需额外工程。

### A.2 反记忆臂：后截止实卡（N）+ 虚构变换（F0–F3）

**首选臂 N：cutoff 之后实装的新版本实卡。** 在明确被测模型训练语料截止时间的前提下，直接用该时间之后官方版本实装的卡牌与卡组（如 cutoff 早于 v6.6 发布，则用 v6.6 卡组）作为"未见过"对照组。相比虚构扰动，它难度天然合理（官方平衡）、无构造退化风险、卡已实装于 `@gi-tcg/data` 引擎直接可执行、生态效度高。但它**只控制"见过这张卡"，不控制"见过这个机制"**——新卡大量复用旧机制模板（3 费战技、回合末召唤物等），机制层面的记忆迁移仍在，控制强度介于 F0 与 F2 之间。且有三个前提必须落实，见 A.4 与 A.7。

**次选臂 R：真实卡的卡组级重组。** 不造新卡，用已实装的真实卡拼出语料中从未出现过的 30 卡卡组表——材料取自母版池、历代比赛卡组与线上卡组数据库（仓库已有米游社合集与召唤之巅 API 文档，见 `卡组收集/`）。工作量近零：无 custom-data-loader 注册、无新卡标注，引擎直接可执行。控制强度介于 N 与 F0 之间——控制的是"见过这张卡组表"，单卡与机制记忆全部保留（这既是局限也是用途，见 A.3）。相比 N 臂的独特价值有三：

1. **无 cutoff 依赖**：所有被测模型共用同一套题，横评不缩水，补 N 臂最大短板；
2. **暴露度可量化**：有卡组数据库即可计算某张完整卡表 / 三人组 / 角色对在语料中的出现频率，把反记忆从"见过/没见过"的二元控制升级为"暴露度 vs 成绩"的回归——协同知识泄漏（语料里有三人组攻略但没有这张表）从混淆变量变成可测量的协变量；
3. **剂量-反应曲线**：以母版卡组为原点按替换距离分级（换 k 张牌、换 1 个角色），score(k) 曲线形状直接区分检索与推理——背了攻略的模型在小 k 处保持高分且随 k 缓降，真做卡组级推理的模型成绩与 k 弱相关。

约束：重组必须保持卡组连贯，否则分析问题失去意义（无 game plan 的卡组谈不上 L1/L2 分析）。做法是**archetype 内重组**——行动卡按母版 ground-truth JSON 的 `keyCards.role` 标注同位替换（damage/draw/sustain/disruption/ramp/flex 角色不变），角色三人组从数据库中选"未共现但元素构成合法"的组合。注意引擎单局只跑一个版本，历代卡组的牌须映射到同一版本卡池的现行定义；旧版本卡组的主要用途是暴露度标定，不是跨版本混组。

**虚构臂 F0–F3 保留**，从弱控制到强控制逐级剥离"可回忆性"，用于剥离 N、R 两臂都测不出的机制模板记忆：

| 级别 | 变换 | 剥离什么 | 难度配对性 | 标注成本 |
|---|---|---|---|---|
| F0 换皮重述 | 仅改卡名、描述措辞、卡图，数值与机制不动 | 表面字符串记忆 | 完全保持 | 零（脚本生成） |
| F1 数值同构扰动（**降级为可选**） | 在 F0 基础上对每张卡做保型扰动：费用 ±1、伤害/治疗 ±1、HP ±2、充能 ±1；技能类型、触发时机、目标选择、机制图保持同构 | 数值记忆（"2费打3"式的定式联想） | **不保证**——±1 费/伤足以改变卡组定位（斩杀窗口、费用节奏对数值敏感），同构 ≠ 难度不变；采用前必须过 A.5 的胜率校验门槛，扰动后对固定 baseline 胜率变化超出容差带的样本拒收 | 低：同构映射可半自动生成 ground-truth JSON 的数值字段 |
| F2 跨体系重组 | 从不同母版拆技能与卡牌重组新角色、新体系（如把召唤物轴嫁接到充能型角色上），制造语料中不存在的 combo | 体系/meta 记忆 | 不保证——需用引擎对固定 baseline 实测胜率校准难度 | 高：人工重标注 |
| F3 规则变体 | 改动游戏级参数（骰子数、能量上限、自造关键词/新反应类型） | 规则本身的记忆，测 L0 规则落地能力 | 不适用（难度维度已变） | 高：规则文本需重写 |

**三臂分工**：N 臂承担卡面级新颖性 + 难度配对（cutoff 后新卡）；R 臂承担卡组表级新颖性 + 暴露度量化（真实卡的未见过组合）；F2/F3 承担机制/规则级新颖性（N、R 都测不出的机制模板迁移）。F0/F1 降级为可选补充。

### A.3 配对判读

主指标为三级记忆泄漏估计量：

- `Δ_card = score(R_old) − score(N_new)`：同一被测模型在 cutoff 前旧版本卡组（v6.3.0 母版池）与 cutoff 后新版本卡组上的成绩差，估计"具体卡面+数值记忆"的贡献；
- `Δ_deck`（R 臂，不用单点差值而用两个形状量）：①暴露度回归斜率——成绩对卡组表/三人组语料频率的回归显著为正即检索依赖的 direct evidence；②剂量曲线 score(k)——小 k 高分 + 随 k 缓降 = 背攻略，与 k 弱相关 = 真推理。R 臂对 L0/L1 无效（卡皆真卡，单卡题靠记忆即可答），只用于 L1 卡组级综合题及以上层级；
- `Δ_mech = score(N_new) − score(F2/F3)`：新版本实卡与虚构重组/变体上的成绩差，估计"机制模板记忆"的贡献——新卡虽未见过，但机制是旧的，若成绩仍高而 F2 掉分，说明迁移靠的是机制先验而非推理。

F0→F3 逐级提供补充归因粒度：F0 掉分说明依赖名称联想，F2 掉分说明依赖体系先验，F3 掉分说明依赖规则记忆本身。报告时按 §5.3 将各臂子集分开，并标注所用臂与级别；跨模型横评时须注意各模型 cutoff 不同导致的 N 臂共同子集缩水（见 A.7），R 臂无此问题。

### A.4 低预训练概率的验收（生成后必过检）

1. **识别测试**：把虚构卡/新版本卡描述给被测模型，要求其猜对应的真实卡——期望失败或乱猜；猜中率高说明控制失效。**对 N 臂，此项是 cutoff 假设的实测验证，不可省略**：厂商声明的 cutoff 与有效 cutoff 常有出入（持续预训练、RLHF 数据注入、版本前瞻/泄露内容可能早于实装进入语料），信声明而不实测是本臂最大的失效风险；
2. **金丝雀词**：虚构批次注入自造关键词（如"虚骰""逆共鸣"），若模型声称见过或能"引经据典"解释其出处 → 该批次作废；
3. **困惑度对照**：虚构描述与真实卡文本在同模型下的 perplexity 应无显著差异——排除"文本太怪所以不会答"这一混淆变量（N 臂为官方文本，天然免于此项）；
4. **deck code 重新生成**：虚构卡组不复用真实分享码字符串（分享码本身可能被语料收录）。

### A.5 合法性与可玩性约束（引擎校验）

虚构变换产物必须过引擎校验才算合格样本：30 张卡组合法、元素共鸣资格成立、费用曲线在 8 骰节奏内可行（L2 金标准能算出非退化结果）、对 random baseline 胜率不过低（否则 L3 matchup 问题失去意义）。**F1 额外加胜率容差门槛**：扰动前后对固定 baseline（§3.6）的胜率差须落在预设容差带内，超出即拒收——这是"难度近似保持"假设的实证检验，不过检的 F1 样本不得用于 Δ 估计。不合格样本回到变换步骤重新采样。N 臂使用官方实装卡，天然满足合法性，但需补足 ground-truth 标注（当前 v6.6 仅 1 套标注，尤其 L3 matchup 标注需随版本补做）。

### A.6 实现路径（对接现有设施）

- N 臂：直接复用 `@gi-tcg/data` 实装数据与引擎的版本选择能力，按被测模型 cutoff 选定对照版本对（如 v6.3.0 母版 vs v6.6 新卡）；L0–L2 金标准与真实组同一管线产出；需补做的是新版本卡组的 ground-truth 标注；
- R 臂：素材为 `卡组收集/`（米游社合集、召唤之巅 API）与母版池分享码，deck code 解码用 `scripts/decode-decks4.ts`；重组生成器按 `keyCards.role` 约束同位替换 + 数据库共现频率过滤（三人组/卡表频率 = 暴露度协变量，随题目一同入库）；零引擎改动；
- 注册（虚构臂）：用 `CustomDataLoader.loadMod()` 加载 mod 脚本注册虚构卡——builder 名称参数即卡名，id 自 10_000_000 起自动分配，`version.from === "customData"`；描述与占位图经 `registerDescription` / `registerImage`（缺省自动用 SVG 占位图，见 `packages/custom-data-loader/src/index.ts`）；
- 金标准：L0/L1 从注册后的 `GameData` 静态解析；L2 照常由引擎蒙特卡洛/搜索产出——引擎执行的是自定义定义，oracle 性质不受虚构影响；
- 标注：F1 的 ground-truth JSON 由同构变换脚本从母版标注半自动生成（仅数值字段映射）；F2/F3 与 N 臂新版本卡组人工重标注；
- 生成器：变换脚本 + 固定种子入库，保证虚构集可复现。

### A.7 污染防护与轮换

本仓库公开，虚构卡数据一旦入库，未来可能进入新模型的预训练语料，反记忆控制随之失效。因此：

- **生成脚本 + 种子入库，数据本体不入库**——虚构集本体放评测私有目录或 CI artifact；
- **每期评测轮换虚构集**：换种子重新生成，旧批次视为已污染，不再用作能力证据。

N 臂的污染防护由官方版本节奏天然供给（约每 6 周一版新卡），旧版本一旦早于被测模型 cutoff 即自动失效、换新版本即可，无需自造。但代价有二：**供给有限**——单版本可用新卡/新卡组数量少，样本量受限，统计功效需按 answer20260728 §4.2 核算；**cutoff 异质**——各被测模型 cutoff 不同，N 臂题目集须按模型定制，跨模型横评只能报告 cutoff 交集内的共同子集，交集可能很小甚至为空（此时退化为逐模型单独报告）。
