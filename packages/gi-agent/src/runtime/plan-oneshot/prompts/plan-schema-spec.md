# GamePlanV1 rule semantics and closed field set (a wrong `when` field fails validation)

- rules are a "policy", not a script: at every decision point the engine first checks the `when` of each phase (the first fully-true phase takes effect), then scans rules in ascending `priority` (smaller number = higher priority); the first rule whose `when` is fully true **and** whose `then` matches a legal action takes effect. If nothing matches, the fallback applies. When a phase rule and a global rule share a priority, the phase rule wins (priorities must be unique within the same chain).
- `when` condition: `{ "field": field, "op": "<="|">="|"=="|"!="|"<"|">", "value": value }`; `value` may be a `"$field"` reference to another field (e.g. `"$self.active.maxEnergy"`). `value` may only be a number/string/boolean.
- Available fields (closed set; anything else is illegal. Types are annotated — a mismatched comparison is always false):
  - `round` (number, round number), `actionsTakenThisTurn` (number, actions your side has already taken this round, including the current decision, starting at 1), `phase` (string, the currently effective phase id, `"none"` when no phase matches);
  - **use `turn` with care**: it is the "current actor index" (0 or 1), not the round number! At action-decision time it always equals your own side's index and carries no information. Use `round` when you need to judge by round number.
  - `self.active.{hp,energy,maxEnergy(number), aura,defId,element(string), alive(boolean), satied(boolean)}`, `opponent.active.{...}` (aura values none/cryo/hydro/pyro/electro/dendro/cryo_dendro);
  - `self.characters.<character defId>.{hp,energy,maxEnergy,alive,satied,aura}`, `opponent.characters.<defId>.{...}` (alive/satied are booleans — write `alive == true`; `alive >= 1` is always false. **satied = that character has eaten food this round (satiated status)**; the `when` of a food rule must include the target character's `satied == false`. **aura = the elemental aura of a benched (non-active) character**, used to predict reactions after a switch);
  - `self.aliveCount` / `opponent.aliveCount` (number);
  - `dice.total` / `dice.omni` / `dice.<element>` (cryo/hydro/pyro/electro/anemo/geo/dendro) / **`dice.<element>+omni` (that element + omni dice total, the standard field for elemental-cost checks)** — note there is no `self.` prefix;
  - `hand.count` / `hand.hasCard.<card defId>` (boolean) / `hand.countWithTag.<tag>`;
  - `opp.hand.hasCardP.<card defId>` (0–1 probability): hypergeometric estimate that the opponent's hand holds ≥1 copy of that card (pre-game open-deck prior: k = copies in the opponent's deck list, h = opponent hand size, U = h + opponent remaining deck; **it does not track cards the opponent has already played, so it overestimates as the game progresses**). The opponent's hand contents themselves are invisible — this is a probability, not a fact;
  - `self.summons.count` / `opponent.summons.count` / `self.supports.count` / `opponent.supports.count` (number);
  - Opponent tempo facts (the opponent's dice faces and hand contents are invisible, but **counts and flags are visible**): `self.declaredEnd` / `opponent.declaredEnd` (boolean, whether they have declared end — when the opponent has declared, all remaining actions this round are yours, so finish slow actions freely), `opponent.dice.total` (number, the opponent's remaining dice — few dice = a safe window in which the opponent can hardly act), `opponent.hand.count` (number, opponent hand size).
  - Opponent-turn threat (player-perspective **derived estimates: upper bounds/probabilities, not exact values**; semantic details in field_reference): `opp.threat.maxDamage` (number, upper bound of the opponent active character's "maximum damage in one action" = max over skills payable within their dice count of base damage + reaction bonus against our active's aura), `opp.threat.lethal` (boolean, maxDamage ≥ our active HP + visible shields — "the opponent can kill me in one action" is written directly as a condition), `opp.threat.lethalP` (0–1 probability, the maximum dice-payment probability among kill-qualifying skills; lethal is the upper bound and lethalP the probability, so the primary defensive trigger should start from >= 0.5), `opp.threat.burstReady` (boolean, opponent active has full energy and enough dice for the burst cost), `opp.threat.burstP` (0–1 probability, a dice-distribution estimate that the opponent can actually pay the burst cost; always 0 when energy is not full), `opp.threat.maxDamageAfterSwitch` (number, upper bound of the opponent's switch + skill two-action damage). Use them for defensive rotations / damage-absorbing rules; opponent hand damage boosters (仙跳墙/resonance/quick switch) are invisible and not part of the estimate.
- `then`: `{ "action_case": "useSkill"|"playCard"|"switchActive"|"declareEnd"|"elementalTuning", "skill_type"?: "normal_attack"|"elemental_skill"|"burst", "skill_def_id"?: skill id (the `#<id>` listed in the deck detail; only `useSkill`), "card_def_id"?: hand card id (must be in your own deck list), "card_tag"?: "tag", "require_tag"?: "tag", "target"?: "opponent.active"|"opponent.benched"|character defId (number), "damage_min"?: n, "kills"?: true, "prefer_reaction"?: ["melt",...] }`.
  - **a numeric `target` is always a character definition id** (the number listed in the deck detail), never any runtime id.
  - **`useSkill` target semantics**: the opponent-side target of the skill's damage — `opponent.active` / `opponent.benched` / a numeric opponent character defId; a candidate matches only if its damage preview hits that target.
  - **`skill_def_id` (only `useSkill`)**: names one exact skill by the `#<id>` shown in the deck detail — use it when the character has several skills of the same type (e.g. Nahida's two elemental skills 17032 3草 / 17033 5草, Oceanid 22012/22013) so the rule targets the intended one; it may be combined with `skill_type` (both filters apply), and when omitted the engine matches by `skill_type` among the variants. The id must belong to one of your deck characters.
  - **`switchActive` target semantics**: the defId of the character to switch in (must be in your own deck list); the engine compares it with the candidate's switch-in character.
  - **`playCard` target semantics**: the character the card targets (numeric defId; may be your own or the opponent's character); which card is played is selected by `card_def_id` / `card_tag` / `require_tag`.
  - `card_tag` / `require_tag`: `playCard`-only hard filters on the played card's definition tag, matched case-insensitively against the exact English tag token listed in the deck detail (they currently behave the same; use either).
  - `prefer_reaction`: a soft preference only (tie-break among multiple candidates of the same rule, never a filter). Full value set: `melt`, `vaporize`, `overloaded`, `superconduct`, `electro_charged`, `frozen`, `swirl_cryo`, `swirl_hydro`, `swirl_pyro`, `swirl_electro`, `crystallize_cryo`, `crystallize_hydro`, `crystallize_pyro`, `crystallize_electro`, `burning`, `bloom`, `quicken`, `lunar_electro_charged`, `lunar_bloom`.
  - kills/damage_min are judged from the action's damage preview; `prefer_reaction` is only a preference among multiple candidates of the same rule.
- `opening` entries also accept `when` conditions from the same closed field set, evaluated in array order: `opening.chooseActive[]` (`when` → `characterDefId`), `opening.mulligan[]` (`keep`/`toss` by `cardDefId` or `cardTag`), `opening.reroll[]` (`when` → `keepElements` from `cryo/hydro/pyro/electro/anemo/geo/dendro/omni`, optional `minKeep`).
- `phaseId` charset is `^[A-Za-z0-9_-]+$` — use English ids such as `early_game` / `mid_game` / `burst_window`; `:` is forbidden because it is the separator in `phase:<phaseId>:<priority>` ruleRefs.
- `fallback.policy` closed set: `"baseline"` (hand the fallback to the engine's built-in heuristic baseline policy) / `"conservative"` (declare end if available, otherwise the lowest-cost action) / `"declare_end"` (declare end directly).
- Every rule must have a non-empty `reason` (it enters the execution log and post-game attribution).
- The execution log counts "when fully true but then zero matches" per rule (the dead-rule probe) — a rule with correct conditions but a wrong target/card is flagged as a dead rule and enters the reflection data.

# declareEnd discipline (important)

- `declareEnd` is allowed in only three cases: ① it is the only legal action (dice/cost exhausted); ② it has a clear tactical purpose (grab first-mover by ending the round early, or keep key cards for the next round); ③ as the lowest-priority last resort.
- Do not treat `declareEnd` as the default "I don't know what to do" action. As long as meaningful actions remain in a round (damage, applying elements, drawing, equipping, charging), there should be a rule covering them.
- You must include at least one low-priority general offensive fallback rule (a `useSkill` / `playCard` with loose `when` conditions) so unforeseen positions still have an action to execute instead of falling into `declareEnd`.

# Rotation discipline (switchActive, important)

- Switching is a slow action: after switching the turn passes to the opponent — every switch gives away one action, and is only worth it when "the next action value of the incoming character > the current character's action + one action of tempo".
- Evaluate rotation at least once per round, and write both kinds: ① **offensive rotation** — a full-energy character is benched and the opponent active is countered by another of your characters (better element/skill efficiency), so switch in for a higher-value action; ② **defensive rotation** — save a near-death character, or switch a high-HP/shield slot in before the opponent's full-energy burst ("the opponent can kill me in one action" is written directly as `opp.threat.lethal == true`; you do not need to compute the kill line yourself).
- Do not write only defensive switches. In post-game attribution, "the plan did not switch while the optimal play was to switch" is the single most common failure class; a benched character with energy ready usually should rotate in.
