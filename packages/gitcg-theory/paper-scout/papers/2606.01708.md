# Two-Fidelity Best-Action Identification for Stochastic Minimax Tree (2FFS)
- arXiv ID: 2606.01708
- Authors: Peter Chen, Xi Chen
- Date: 2026-06-01
- Relevance Score: ⭐⭐⭐⭐⭐

## Summary
2FFS addresses the fundamental tradeoff in modern MCTS: heuristic evaluations are cheap but biased, while accurate (e.g., LLM-based) rollouts are reliable but expensive. The algorithm brings multi-fidelity bandit ideas into minimax trees, adaptively deciding when to use cheap biased evaluations vs. expensive accurate ones. Proves fixed-confidence correctness and polynomial-depth cost bounds. Substantially reduces sample/computation cost vs. baseline BAI-MCTS.

## Key Contributions
- **Multi-fidelity MCTS**: First principled framework combining cheap heuristic + expensive accurate evaluations in minimax tree search
- **Adaptive budget allocation**: Algorithm decides per-node whether to use fast (biased) or slow (accurate) evaluation
- **Theoretical guarantees**: Fixed-confidence correctness, finite stopping for exact identification, polynomial-depth cost upper bound
- **Practical efficiency**: "Substantially fewer samples" vs BAI-MCTS baseline in numerical experiments

## Connection to Our Work
- **MCTS compute budget optimization**: GI TCG rollouts are expensive (game engine simulation); 2FFS could interleave cheap GBDT heuristic evaluations with full game engine rollouts
- **LLM rollouts**: If we use LLM-based value estimation in MCTS, the cheap-biased/expensive-accurate tradeoff is exactly what 2FFS addresses
- **Action pruning synergy**: Combine 2FFS adaptive sampling with action space pruning for even more efficient search
- **Theoretical rigor**: The fixed-confidence framework provides guarantees we currently lack in our MCTS implementation

## Critical Assessment
**Strengths**: Strong theoretical foundations, directly addresses a real MCTS bottleneck, polynomial cost bounds are practically useful. Clean algorithm design.

**Weaknesses**: Numerical experiments only (no real game environment), no code released. Theoretical focus may make practical implementation non-trivial. Single algorithm variant (no exploration of different fidelity models).

**Reproducibility**: Moderate — algorithm is mathematically specified but no reference implementation. Would require implementation from scratch.
