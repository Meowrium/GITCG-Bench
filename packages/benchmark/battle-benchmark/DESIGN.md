## 一、定位

测量 LLM 在**实时对战过程**中的两类能力：

1. **对局执行能力**：在信息不对称、骰子随机、对手对抗下的逐决策质量；
2. **自我改进能力**：把对局层证据回写为陈述层知识的能力——即跨越静态分析硬边界（`analyzer-static-limitations-and-fixes.md` 不可修复三项）的"模拟 → 知识"提升。

设计公理（来自理论地基，不再展开论证）：

- **层级轴**：L0 单卡 → L1/L2 卡组内秉 → L3 对局 → meta。每层有唯一合适的测量仪器；跨方高体项与 meta 期望**只能通过对局测量**（弱涌现），这正是本 benchmark 存在的理由。
- **对战结果不是 ground truth**：胜负被骰子/抽牌/先后手污染，只作反思评分的输入，不作正确性标签。
- **非传递性 ⇒ 拒绝标量总分**：报告一律为 matchup 矩阵 / 学习曲线族 / 违规率向量，不合成单一 Elo 或"自我改进总分"。
- **免标注**：每条检查项必须指向可计算判据（§三 Oracle 表）。写不出判据的维度，宁可不测（§九）。

## 二、自我改进的能力拆解

笼统的"越打越好"不可测（WR 漂移可能只是噪声）。拆为六个可独立测量的子能力：

| # | 子能力 | 定义 | 度量 | Oracle |
|---|--------|------|------|--------|
| S1 | 归因正确性 | 反思把胜负归因为分析错误 vs 随机性，归得对不对 | "应做 X 不做 Y"→ 种子复现交叉验证（§五 评测 C） | O4 |
| S2 | 记忆与调取 | 复访同 matchup 时是否使用历史修正 | 复访时预测/行为变化 × 记忆擦除对照（§六） | O3+对照 |
| S3 | 收敛性 | 修正方向稳定而非摇摆；预测误差随轮次缩小 | 校准误差-轮次曲线 + 方向一致性追踪 | O5 |
| S4 | 迁移 | A vs B 学到的修正泛化到 A vs C | 留出 matchup（§六.4） | O5 |
| S5 | 执行层改进 | 信息使用错误与 verified blunder 随轮次下降 | Tier 1 违规率 + Tier 2 verified blunder 率（§四） | O1/O4 |
| S6 | 保持 | 间隔若干其他 matchup 后，旧知识是否存活 | 间隔复测（§六.4） | O3+对照 |

**S5 单列的理由**：分析变准 ≠ 打法变好（`missing-modules-guiding-questions.md`：缺 game-level 时下面两层无法正常生成）。拆开测才能定位断点住在哪一层。

## 三、免标注 Oracle 表

| # | 来源 | 可测内容 | 判据性质 |
|---|------|---------|---------|
| O1 | 规则引擎（规则即代码） | 事实断言、序列合法性、费用、斩杀线、元素×反应表、状态一致性 | 精确 |
| O2 | 机制定义的干预配对 | 对高阶项的敏感性（局面只差一个机制，正确变化方向由机制定义） | 精确 |
| O3 | LLM 自身（自洽性） | 计划 vs 执行、威胁评估 vs 实际应对、预测 vs 行为 | 精确（以模型自己的话为参照物） |

**O4 的技术前提（v0.5 延后启用）**：`GameConfig.randomSeed` + `DeckConfig.shuffleSeed` 引擎已支持，但 headless runner 未接入。当前 benchmark scope **不涉及反事实推理、不固定种子**，统计功效由样本量保证；反事实验证（Tier 2/评测 C 归因）需要时再启用种子接入（届时列为 P0）。注：`gitcg-theory/02` 的 AdvantageWorker 仅为方案文档（含 stub），无现成实现，启用时从零建设。

**参考 AI 的使用限制**：GiMlPolicy/MCTS 自身偏科（红牛镜像 100% WR 在案），只可用于**配对比较**与引擎已验证子集，不得作为绝对标准。

## 四、决策审计插桩（三层结构，每局附带）

> v0.2 重写。**设计原则：战略最优性不存在无例外的局部判据。** v0.1 把 `action-rationality-constraints.md` 的诊断速查表直接当作计分规则，但评审指出每条启发式都有合法反例——而这些反例恰恰是高阶相互作用项的体现（防反打 = 跨方耦合，蓄爆 = 战略折现，切人消耗 = 对手资源耦合）。用局部规则给战略打分与弱涌现结论直接矛盾：凡是涉及战略好坏的判定，必须交给模拟（O4），局部规则只能做两件安全的事——**判信息使用**（无例外）与**做抽样线索**（不计分）。

### 4.1 Tier 1：信息使用层（精确判据，计分）

只有"忽视已可得信息"与"自相矛盾"构成无例外的错误——它们不涉战略判断，只涉模型是否用好了输入：

| 检查项 | 判据 | Oracle |
|--------|------|--------|
| 非法动作尝试 | `choose_action` 非法 index / 费用不足 / 目标不存在（引擎拒绝即事实） | O1 |
| 幻觉卡牌 | 引用卡组外或场上不存在的牌（对照 digest 中的 `card_definitions`） | O1 |
| digest 误读 | digest 已显式给出的信息（`kill_threats`、对手已展示的牌、费用/伤害预估值）在决策理由中被否认或无视 | O1+O3 |
| 自相矛盾 | 陈述意图与实际动作直接冲突（声称"先充能"却打出伤害技） | O3 |

**两条边界（v0.4）**：
- 非法动作尝试必须在 **sanitize 之前的原始工具调用层**审计——若工具层先过滤非法请求，`game_replay` 里测不到真实违规率（对应 §7.1 的 `rawRequest`）；
- 幻觉卡牌只针对 **digest / 已展示信息集**（卡组内、场上、对手已展示的牌）；对"对手隐藏手牌具体持有某牌"的猜测属预测，不是幻觉，不入 Tier 1。

### 4.2 Tier 2：战略判定层（反事实验证后才计分）

原速查表降级为**抽样线索**。流程：线索命中 → 种子复现到决策点 → fork K 条 rollout 比较候选动作 → **仅当替代动作显著更优（A>0 且 CI 不含 0）才记为 verified blunder**。防反打、蓄爆、资源交换等反例由模拟自然吸收（fork 中包含对手响应），无需人工枚举例外——这正是"局部规则失效 ⇒ 交给模拟"的弱涌现原则，也回应了"判据不好"的评审意见：**坏的判据不再担任判据，只担任线索**。

**启用条件（v0.5）**：上述验证流程依赖固定种子机制；当前 scope **默认只报 flag 率并显式标注"未验证"**，反事实验证在需要时随 O4 机制（种子接入 + 重放引擎）一并启用（§八"延后启用"项）。

| 线索（原判据） | 已知合法反例（评审意见） | 修订后处置 |
|--------------|------------------------|-----------|
| 可斩杀未斩杀 | 防反打、留残血控场 | flag → 验证；不杀是否更优由 rollout 判定 |
| R1 高比例打牌 | 蓄爆体系在后续回合发力，相当部分情况合理 | 默认不 flag；仅当后续回合出现骰子闲置/断档时 flag → 验证 |
| 循环切人 A→B→A | 消耗对手骰子的降速策略 | flag → 验证（消耗是否值得由模拟判定，而非规则断言） |
| 支援被秒解 | 必要的资源交换，不能无限防 | 仅当反制牌属**已公开信息**（对手此前展示过）时升入 Tier 1 计分；否则不 flag |
| R4+ 打低 ROI 支援 | 反例较少但仍存在 | flag → 验证（保留） |

**计算预算（v0.4 修订）**：LLM 实时对战成本已很低（deepseek-v4-flash 级模型 ~0.1–0.2 元/局），成本不再约束 rollout 规模——每局限额与 K 可放宽（默认 K=20–50）；"降级为只报 flag 率并显式标注**未验证**"保留为工程质量护栏，不再是成本驱动的默认路径。**续走策略（v0.4 再修订）**：rollout 的续走策略**沿用被测 LLM 本身**（2026-08-01 决议）——O4 的 advantage 即为"被测 LLM 自身策略下"的条件度量，报告注明"当前策略下"即可；K 与续走配置均为可配置项并写入 `config.json`。绝不允许把 flag 率当 blunder 率报。

### 4.3 Tier 3：行为画像层（只描述，不计分）

R1 骰子分配、切人频率、部署率、反应触发率等作为连续行为描述符（`archetype-classification-impossibility.md` §四的行为谱），用于追踪跨轮次打法漂移（S3 收敛、S5 的输入），**不标记对错**——v0.1 中按阈值计分的 R1 骰子项移入本层。

### 4.4 WR 统计的分层对比规则

**一切 WR 对比只在 （我方卡组 × 对手卡组 × 先后手） 单元格内进行。** 单元格是 WR 可比的最小单位：同一单元格内允许跨轮次（学习曲线）、跨对照组（记忆开/关）、跨模型对比；跨单元格禁止合并、平均或对比——卡组强度与克制关系无法从混合 WR 中分离（v0.2 评审意见）。聚合呈现一律用 matchup 矩阵，不合成总 WR。

- **镜像只是单元格的特例**（双方卡组相同）：先手优势基线按 **（卡组 × 对手 × 先后手）单元格** 的固定 AI 自对弈 WR 标定（带 CI）；"召唤系先手优势显著更大"只作为卡组/实验设计先验，不作基线；"超出基线的偏差"只在同一单元格内报告。基线是数据，不是 50% 的假设。
- **样本量与显著性**：每单元格需满足最小样本量；二项标准误 `sqrt(p(1−p)/n)`，p=0.5 时 n=400 → ±2.5pp、n=2500 → ±1pp。无 CI 的 WR 一律不报告。
- **最小可检测效应（MDE）**：预算按目标 MDE 反推（p≈0.5 时 n=100 → ±5pp、n=400 → ±2.5pp）。阶段 1 已决为**每臂 100 局**：聚合对比下两臂差 SE≈7pp、95% CI 半宽≈14pp（检测口径 ~14pp，见待评审问题 2）；40–60 局/臂（SE≈±9–10pp）的方案不采纳。
- **与 §6.3 的关系**：单元格内样本可比性由 同卡组 × 同对手 × 先后手交替 保证；**方差缩减不依赖固定种子**（v0.5：当前不固定种子，功效靠样本量）；先后手不交替则单元格定义本身失效。
- **不固定种子（v0.5）**：固定种子会引入"LLM 针对种子集过拟合"的风险（习得特定抽序/骰序下的打法，而非可泛化策略）。对"LLM 是否习得正确策略"的检验一律通过**加大测试数**实现；需要反事实验证时才启用固定种子，且种子只用于评测机制（重放/归因判定），不用于被测模型的学习轮。
- **非镜像 WR 不作违规信号**（v0.2 已定）：只允许上述单元格内的纵向/横向对比。
- **多重比较（v0.4，v0.6 已决）**：学习曲线族横跨多单元格 × 多轮，构成多重检验；主假设预注册，报告区分探索性与确证性——阶段 1 单一主对比无需校正；阶段 2 起确证性全局结论用 Holm（FWER）、多格子发现型结论用 BH（FDR），探索性结果一律标注（待评审问题 5 已决）。

实现位置建议：`packages/gi-agent/src/learning/combat-windows/` 已有日志切窗管线，审计器作为其上的独立模块。**修正（v0.4）**：`gitcg-theory/02` 是方案文档（含 stub，未实现），仓库中不存在可复用的 AdvantageWorker；Tier 2 与评测 C 的"种子重放 → 决策点 fork → K 条 rollout"是从零实现的硬依赖（v0.5：列入 §八"延后启用"项，当前 scope 不排期）。combat-windows 的 branch-eval（replay/policy/best 的 WR lift）是 replay 指纹近似，可作结构参考，但不是精确种子重放。

## 五、评测体系（A–F）

继承 deck-analysis 的评测 A–D 框架，按免标注口径改造，新增 E/F。

### 评测 A：Round 0 静态分析（陈述层基线）
- 内容：LLM 仅凭卡组构成做 L2 分析（开局序列、关键组件、出伤模式）。
- 评分：**O1**（事实与合法性断言，接 `@gi-tcg/test` 的 `setup(<State>)` + `expect` 做 DSL 验证）+ **O3**（留牌建议/条件分支/序列选择的内部一致性）。
- 与 deck-analysis 阶段 1 共用产物，不重复建设。
- **依赖提醒（v0.4）**：deck-analysis 阶段 1（Round 0 评测）当前未实现，需在阶段 0 一并实现或定义降级路径。
- **DSL 边界（v0.4）**：`@gi-tcg/test` 的 controller 为 `alwaysOmni` + `allowTuningAnyDice`（reroll 亦未接入），只能验证"序列可执行"，不能验证骰子颜色可行性；O1 的"费用正确性"按此口径计分并在报告中显式标注。

### 评测 B：预测校准（替代"与专家一致"）
- 内容：每轮战前预测 matchup 方向、节奏偏移、威胁应对。
- 评分：对**大样本模拟统计**的校准误差（Brier score / 分箱校准曲线），带置信区间。**不需要任何人事先知道正确答案**——这是免标注的核心机制。
  （v0.4 定案，回答待评审问题 3）参考分布由**固定 checkpoint 的 self-play** 产出，且与对局对手策略一致；被测模型自身对局统计只用于评测 D 的收敛曲线，不作校准目标——否则校准混入其执行水平。

### 评测 C：反思质量
- 自洽性部分（O3）：输了全推给骰子 → 扣分；"赢了不改且事后被证伪"仅在 O4 反事实执行能判定"坚持的分析确实错误"时扣分（与 §4.2 同机制），无法判定则不判——避免回到不可判的 LLM-as-judge（v0.4 修订）。
- 归因部分（O4）：反思声称"应做 X 不做 Y" → 种子复现同局面，分别执行 X/Y 比对 → 归因对错自动判（v0.5：随 O4 种子机制延后启用；当前阶段只做 O3 自洽性部分）。
- 保留原检查清单中"修正是否过度"条目（O3 可判）。

### 评测 D：收敛性
- 校准误差-轮次曲线（评测 B 的纵向展开）；
- 修正方向一致性（原 DESIGN.md 已有定义：连续一致加分、来回摇摆扣分）；
- 行为收敛：跨轮次的决策分布是否稳定（replay 统计）。

### 评测 E：迁移（新增）
- matchup 池划分 train/holdout；holdout 只允许战前预测，不提供对战迭代。
- 度量：holdout 上的预测校准是否优于 Round 0 基线——迁移发生在"没打过"的对局上才算迁移。

### 评测 F：保持（新增）
- 间隔 ≥3 个其他 matchup 后复访旧 matchup，知识是否存活（对照：紧接复访）。
- 检测"最新覆盖旧知"的灾难性遗忘。

## 六、实验设计（四处关键调整）

### 6.1 对手冻结
对手 = 固定 checkpoint 的 GiMlPolicy/MCTS 或冻结 prompt 的 LLM 快照。因变量必须只含被测模型一个自由变量。
（v0.4 补充）该原则同样约束被测侧：轮次间固定 prompt 模板、temperature、上下文构造，唯一变量是 knowledge 文件；每轮必须全新进程/对话，只注入 `LLMDeckKnowledge`，禁止聊天记录残留——这是 §6.2 无记忆对照成立的前提，列入 P1 验收条件。

### 6.2 对照组（核心，不是点缀）
| 对照 | 操作 | 证伪目标 |
|------|------|---------|
| 无记忆 | 每轮清空 knowledge 文件 | "改进"应消失 |
| 无反思 | 跳过战后反思环节 | 改进应显著减弱 |
| 打乱历史 | 注入其他 matchup 的反思记录 | 检验调取选择性 |

无对照组的"自我改进"断言一律视为伪证。
建议补充 **warm-start 变体**（v0.4）：无记忆臂固定 Round 0 分析、仅禁止迭代修正——隔离"没有记忆"与"没有学习"，避免每轮清空后的冷启动成本与方差。

### 6.3 样本量与种子策略（v0.5 改写）
**当前 scope 不固定随机数种子**：benchmark 不涉及反事实推理，固定种子无必要，且会带来"LLM 针对种子集过拟合"的风险（习得特定抽序/骰序下的打法而非可泛化策略）。对"LLM 是否习得正确策略"的检验一律通过**加大测试数**实现：按 §4.4 的 MDE/CI 口径为每单元格、每对照组预算样本量，并以 matchup 顺序随机化避免系统偏差。先后手交替仍为单元格划分成立的前提（§4.4）。**需要时再启用**：Tier 2 反事实验证与评测 C 归因（O4）实现时，种子接入（`randomSeed`/`shuffleSeed`）列为 P0（§八"延后启用"项）。

### 6.4 轮次结构
- 同 matchup 重复 K 轮（收敛需重复，建议 K≥5）；
- matchup 顺序随机化（测干扰）；
- 间隔复测插入（评测 F）；
- holdout matchup 永不参与训练轮（评测 E）。

## 七、数据契约

### 7.1 对局记录（P1 统一格式）
每局一份 record，替代现存三套并存日志（`headless-logs/`、`p{0,1}_llm.jsonl`、`game_replay.json`）：

```typescript
interface BattleRecord {
  recordId: string
  seed?: { randomSeed: number; shuffleSeed: number }    // 反事实验证启用时必填（v0.5：当前默认不填）
  firstPlayer: 0 | 1                                   // 相对被测侧定义；交替由 runner 对调 deck 槽位实现（v0.4）
  myDeckCode: string; oppDeckCode: string
  dataVersion: string                                  // 游戏/数据版本（runner 已支持 --version）
  opponentPolicy: { kind: "mcts" | "giml" | "llm"; checkpoint: string }  // 冻结标识
  knowledgeRef: string                                 // LLMDeckKnowledge 文件引用（deckCode+version 语义；全局递增号在多 matchup 并发下不唯一）
  decisions: {
    round: number; digestRef: string
    decisionKind: "choose_action" | "switch_hands" | "choose_active" | "reroll_dice" | "elemental_tuning" | "select_card"  // 与 llm-agent 工具名一致（v0.4）
    rawRequest: unknown               // sanitize 前的原始请求（Tier 1 非法动作审计用，v0.4）
    digestSnapshot: TurnDigestV1      // LLM 实际看到的状态表示
    chosenAction: unknown; latencyMs: number; tokenUsage?: number
    auditFlags: string[]              // §四 审计命中项
  }[]
  mutationLogRef: string             // 与决策对齐的 mutation 链（可追溯性判据 (a)）
  result: { winner: "me" | "opponent"; totalRounds: number }
}
```

### 7.2 跨局记忆通道（唯一化）
- `LLMDeckKnowledge`（deck-analysis 已定义）为**唯一**跨局记忆载体；
- `strategy_store` / `sandbox-generator` 统一读写该文件；**禁止依赖原始聊天记录残留**——否则记忆擦除对照无法实现（v0.4 升级为 P1 验收条件：每轮全新进程/对话，只注入 knowledge 文件）；
- `refinedKnowledge` 加长度上限/消融开关，防止"上下文膨胀"冒充"改进"。

### 7.3 产物目录
```
data/battle-benchmark/{runId}/
  config.json                 # 种子池、对手 checkpoint、对照组开关、K、游戏版本 + deck-analysis 标注版本 + 卡池指纹（v0.4 钉死数据版本）
  rounds/round{i}/game{j}.json        # BattleRecord
  knowledge/round{i}.json             # LLMDeckKnowledge 快照
  audits/round{i}.json                # §四 违规率向量

```

## 九、明确不测什么

1. **战略叙事质量**（"这套牌的典型对局是什么样的"类开放叙事）——标注者间一致性必然崩，放弃测量而非降低标准；
2. **LLM-as-judge 整体替代**——推荐用可计算检查项取代 judge；若保留 judge，须一次性校准（20 题、相关性 >0.8，沿用 deck-analysis 约定）；
3. **胜率作为正确性标签**——胜率只作反思评分输入与单元格内对比（§4.4），不作"答对/答错"的判据。

人工仅保留两处：题目措辞一次性审阅（~1-2h）、"不测什么"清单的维护。

## 十三、自进化机制选型（被测机制，v0.7）

**定位**：本节选定的是**被测机制**（mechanism under test）——LLM 把对局证据回写为知识的具体算法。它是测量对象而非测量仪器：§三 Oracle、§六 对照、§4.4 单元格纪律全部不变，框架的每个组件都必须能映射为一条可消融的对照臂。

五篇依据论文同属 EoH（Evolution of Heuristics）谱系：进化单元 =（产物，思想）二元组 + I1/E1/E2/M1/M2 prompt 算子族（I1 从零生成；E1 完全不同形式；E2 提取父代骨干后合成变体；M1 自由修改；M2 只调数值参数）。草案此前的"赛后反思改写 knowledge"相当于只有 M1 算子的退化 EoH；本节把它补全为完整框架。

### 13.1 主框架：MeEvo 双层循环

- **NE 层（自然进化）**：打 1 局 → 反思 → 用 EoH 算子更新 knowledge；对应 §6.4 的 K 轮结构。
- **ME 层（元认知进化）**：每 N=2 轮 NE 做 M=1 次跨轮 meta-reflection（节奏 2:1 起步，写入 config 可调）：读**不可变历史**（BattleRecord + 历史 iterationLog + 违规率/校准曲线）→ 产出 Meta Insight（收敛诊断[过早收敛/稳步/振荡/停滞] / 局限分析 / 路径建议 三段式）→ 指导下一轮反思策略。推理轨迹只读、永不改写，与 §7.1 BattleRecord 的 append-only 语义一致。
- **选型理由**：五篇中唯一为"评估昂贵且含噪"场景设计的框架——用反思从历史中榨取信号，而非大种群暴力搜索；双层结构与"对局执行 + 反思写回"天然同构；其消融臂（纯 NE / 纯 ME / 组合）与 §6.2 对照组一一对应。

### 13.2 嫁接组件

1. **A-CEoH（可执行上下文注入）**：所有生成类 prompt（Round 0 分析、反思、meta-reflection）注入可执行上下文——digest schema、工具 API、规则代码——而非人工问题描述；与"deepseek-v4-flash 级模型 + 好上下文"的成本路线（v0.4）一致。
2. **CoupleEvo（分节 + iterative 协调）**：`LLMDeckKnowledge` 拆为固定分节（骰子管理 / 出牌与技能节奏 / 切人时机 / matchup 专项，v0.8 定案），每轮反思只进化**一个**分节、轮流进行（iterative 策略）；**禁止一个 prompt 整体重写**（其 integrated 策略已被实验证伪：方差大、成功率低）；分节 + 单节长度上限同时缓解 §十二"上下文膨胀冒充改进"。
3. **RAISE（对抗 matchup 课程）**：训练侧周期性运行**零 LLM** 的卡组空间对抗搜索（内层经典 EA + ε-ball 分布锚定；受害者用引擎 AI 粗筛、被测 LLM 只验证 top 候选），把暴露当前 knowledge 失败模式的 matchup 加入训练池；测量侧（holdout、对手冻结）不受影响。**ε-ball 约束不可省**（其消融：无约束对抗反而有害，+205%）；对抗 matchup 必须锚定真实卡组分布附近。

### 13.3 明确不采纳

- **DGS（双代理引导生成选择）**：其前提是评估便宜且量大（毫秒级 × 数百次）；对局评估的数据量训练不动代理模型。降级为**埋点**：每次 knowledge 更新记录 （算子， 父代， lineage id) 元数据进 iterationLog，留待日后数据充足时启用学习式选择。
- **大种群精英截断**（EoH 系默认 20 种群 × 每代 80 候选）：与 §4.4 MDE 口径冲突（每候选 ~100 局才有 ±7pp 分辨力）。knowledge 变体维持 1–2 条 lineage，一切比较只在同单元格内进行。

### 13.4 组件-对照臂映射（§6.2 扩展）

| 对照臂 | 框架语义 |
