# ReAct: Synergizing Reasoning and Acting in Language Models

- **arXiv ID**: [2210.03629](https://arxiv.org/abs/2210.03629)
- **Authors**: Shunyu Yao, Jeffrey Zhao, Dian Yu, Nan Du, Izhak Shafran, Karthik Narasimhan, Yuan Cao (Princeton, Google Brain)
- **Date**: 2022-10-06
- **Venue**: ICLR 2023
- **Citations**: High (foundational paper)
- **Relevance Score**: ⭐⭐⭐⭐⭐ (5/5 — Agent 基本循环的奠基论文)

## Summary

首次提出让 LLM 以交错方式同时生成 **推理轨迹（Thought）** 和 **任务特定动作（Action）**。推理轨迹帮助模型诱导、追踪、更新行动计划并处理异常；动作为模型提供与外部环境交互以收集额外信息的接口。在 HotpotQA（问答）和 Fever（事实验证）上超越纯 Chain-of-Thought，通过与 Wikipedia API 交互克服了幻觉和错误传播。

## Key Contributions

- **Thought-Action-Observation 循环**：定义 LLM Agent 的基本交互模式
- **交错推理与行动**：不是先想完再做，而是边想边做、边做边更新
- **提升可解释性**：显式推理轨迹让 Agent 决策过程可审计
- 通用性：同时验证在 QA、事实验证、文字游戏（ALFWorld）和导航任务（WebShop）上的有效性

## Connection to Our Work

- **Agent 基本循环**：当前管道是 PlanV2 → DecisionFragment → Resolver → Critic 的线性流，缺少显式的 Thought 回溯。ReAct 的 Thought-Action-Observation 循环是最自然的 Agent 化改造——DecisionFragment 增加 `reasoning_trace` 字段，下一步的 TurnDigest 带有上步的 reasoning_trace 作为 context 前缀。
- **边做边想的模式**：当前 PlanV2 是「开局想完」+ 「每步执行」，ReAct 的模式是「每步都重新想」。对 GI TCG 这种不完备信息游戏，每步重新想更能适应对手的策略变化。
- **幻觉防范**：ReAct 的 Action→Observation 循环天然防范幻觉——LLM 说「对手有 3 个火骰」，下一步 get_screen_state 验证是否真的有。

## Critical Assessment

**Strengths**: 奠基性论文、设计模式简单清晰、通用性强、可解释性好。
**Weaknesses**: 2022 年的论文，未考虑工具调用规模（MCP 10+ tools）；纯 prompt 约束（不比 tool permission isolation）；无长期记忆机制。
**Reproducibility**: 高——模式简单，只需 prompt 和少量工具。
