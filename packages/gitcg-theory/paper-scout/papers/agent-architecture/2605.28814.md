## 1. Problem & Motivation

Best-of-N 和 tree search 两大局限：
1. **验证信号稀疏** — 只有终局 binary/coarse 反馈
2. **候选生成受限** — 仅靠自回归扩展，困在 entropy shell 内，无法到达低概率但包含正解的区域

## 2. Core Idea: BES (Bidirectional Evolutionary Search)

### Forward Search — 逃离熵壳

四种进化算子 (evolution operators)，灵感来自有性繁殖的染色体重组：

| 算子 | 功能 |
|------|------|
| **Combination** | 合并两个共享前缀的轨迹的后缀 |
| **Deletion** | 删除一个中间步骤 |
| **Translocation** | 将一个轨迹中的一步移植到另一个轨迹 |
| **Crossover** | 将一个轨迹的前缀拼接到另一个轨迹的后缀 |

父节点选择用 Boltzmann 分布，温度从探索向利用退火。
对两父节点算子，用 pair score 偏爱互补性强的父节点对。

### Backward Search — 密集子目标信号

递归分解原任务为可验证的子目标树：
- 每个子目标有独立的 verifier
- 前向节点的得分 = 递归聚合其满足的子目标数
- 定期选取未被满足的叶子子目标继续分解

子目标评分公式：
```
s(n, g) = α · V_g(x, n) + (1-α) · avg(s(n, g') for g' in children(g))
```

### 双父节点配对评分

取两父节点对每个子目标的 max 覆盖，偏爱覆盖不同子目标的互补父节点。

## 3. Theoretical Results

### Theorem 4.4 — Shell Confinement & Escape

**Setup**: 策略 P 生成轨迹 Y = (y₁,...,y_T)，轨迹熵 H_T = H_P(Y)

三个温和假设：
- Assumption 4.1: per-step surprise 有界 (< L)
- Assumption 4.2: 步骤依赖衰减 (β-mixing)
- Assumption 4.3: 块间总相关性线性增长 (≥ γT, γ > 0)

**结论**:
- (a) 纯扩展产生的所有候选以极高概率落在 entropy shell: `A_ε(T) = {y: |-log P(y) - H_T| ≤ εT}`
  壳的大小 ≤ exp(H_T + εT)
- (b) k-time evolution 分布的期望 surprise ≥ H_T + γT，严格超过壳边界
  正比例的进化候选逃离壳

**直觉**: 自回归步骤之间有关联 → 单条 rollout 的 surprise 围绕 H_T 集中。进化算子随机重组不同轨迹的 block → 打破块间依赖 → surprise 增大 → 逃逸。

### Theorem 4.5 — 后向搜索的指数加速

在有 m 个叶子子目标的后向目标树下：
- 终局搜索需 Ω(1/∏p_i) 样本才能有恒定成功概率
- 双向搜索仅需 O(p_min⁻¹ · log(m/δ))
- 对称情况下 (p_i = p)，比例 = Ω(p^{-(m-1)}/log(m/δ)) → **指数级加速**

## 4. Experiments

### Post-Training

| Task | Base Model | Baselines | BES Result |
|------|-----------|-----------|------------|
| **Knights-and-Knaves** (logic) | Gemma-3-1B-it | GRPO/MaxRL 几乎不提升 | 稳定持续提升 |
| **MuSiQue** (multi-hop) 3B | Llama-3.2-3B | GRPO 倒退, Tree-GRPO 持平 | **+3.0pp** (7.0%) |
| **MuSiQue** (multi-hop) 8B | Llama-3.1-8B | GRPO 倒退, Tree-GRPO +0.8pp | **+3.8pp** (10.4%) |

MuSiQue上BES训练出的agent有更多valid search actions和更高finish ratio → agent真的学会了搜索。

### Inference (Open Problem Solving)

Backbone: GPT-5。三个benchmark vs 开源框架：

| Benchmark | OpenEvolve | GEPA | ShinkaEvolve | **BES** |
|-----------|-----------|------|-------------|---------|
| Circle Packing (Sq.) | 2.531 | 2.613 | 2.464 | **2.623** ± .014 |
| Circle Packing (Rect.) | 2.267 | 2.326 | 2.335 | **2.349** ± .012 |
| Heilbronn (Convex) | 0.025 | 0.025 | 0.023 | **0.026** ± .001 |

BES不仅均值最高，且方差显著更低（搜索更稳定）。

### Ablation

去掉 answer reweighting 或 evolution operators 均下降，但都仍优于 GRPO/MaxRL baseline → 各组件均有效。

### 成本

- Post-training: BES 比 Tree-GRPO 多 < 30% walltime，性能大幅提升
- Inference: BES 比 ShinkaEvolve 多 $4-6 API 成本，均值稳定提升

## 5. Key Takeaways for GI TCG

1. **后向目标分解** → 直接映射到 CGT 的 cold/hot/Number 分类：将"胜率"分解为可验证的子目标（骰子质量、手牌质量、HP优势、场面存在、先手优势），每个子目标独立验证
2. **进化算子生成训练样本** → 可借鉴：在 MCTS 搜索中不只扩展，还可以 crossover 两条 promising 的 rollout
3. **密集信号** → BES 的核心洞察：稀疏奖励下搜索效率低，必须有中间反馈。GI TCG 的 GBDT 评估器天然提供中间状态评分
4. **Shell confinement 理论** → 解释了为什么纯 MCTS 在某些问题上效率低，仅靠扩展受限
