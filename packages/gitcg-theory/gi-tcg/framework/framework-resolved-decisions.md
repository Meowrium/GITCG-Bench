## 〇、引擎对齐的硬空白

### 0.1 击倒后的强制结算窗口

- **【决议】** 击倒是当次伤害结算的**同步副作用**（`alive=0` / `energy=0` / `aura=None` 同帧完成），非独立操作。
- **【决议】** 强制 `chooseActive`：**可以选择出战角色时算作单独行动**；但**部分带强制切人效果的击倒会跳过该环节**（引擎直接指定）。【玩家修正】参考答案"统一不算操作"被细化为"可选则单列、被指定则跳过"。
- **【决议】** 同一段伤害链同时击倒双方 active → 建模为**联合 chooseActive**（博弈论同时决策），评估时拿到尽可能多信息为佳。【依据】用户 Q2。
- **【决议】** "打掉一次免死"是**独立 `K_now` 子类**（`K_immune_break`）：结构跳变但角色仍在。免死通常**限定回合/轮次有次数上限**，在下一次"免于被击倒"效果生成前可直接击倒。【依据】P1 + 用户确认。

### 0.2 反应增伤 / 附伤 / 附带效果

- **【决议】** 引擎事实（写死）：反应增伤是**固定加值**——融化/蒸发/超载 **+2**；超导/感电/冻结/结晶(×4)/燃烧/绽放/激化/月相绽放 **+1**；扩散(×4)/月相感电/月相结晶水 **+0**（仅附带效果）。**全框架禁止用乘法倍率建模。**
- **【决议】** `D_now` 拆项里"反应直接增伤 / 反应附带额外伤害 / 反应附带非伤害收益"三类**合并**，不单列。【依据】P1 + 用户。
- **【决议】** 冻结/眩晕/石化等控制型反应**同时具备 `K_now`（即时压制）与 `T_plan`（未来节奏）特征**，不额外新增 `Control_now` 项。【玩家修正】参考答案给的(a)+(b)合并被确认。
- **【决议】** 月相反应：引擎单列是游戏机制需要；**玩家视角下（可准确选择启用普通/月相）不单列**，并入普通反应表简化框架。【依据】P2 + 用户。

### 0.3 成本类型（ALIGNED / VOID / ENERGY / LEGEND）

- **【决议】** **出战角色 = 第 0 阶资源（状态轴）**：先于骰子决定哪些 ALIGNED 费用手牌可付。命名用中性"决策前置量 / 状态轴"，列为 `s` 最高优先级字段。【依据】P1（Q8）。
- **【决议】** **ENERGY 单列为按角色私有累积的资源池**：`s.energy = [(char_id, current, max)]`，与骰子分轴。非元素爆发兑现路径（白垩之术 332009 / 312014 / 123031 等）归 `E_plan.energy_alt_payoff`，与"开大招"路径并列（P5 多路径）。【依据】P1+P2（Q7 配套）。
- **【决议】** **LEGEND / 秘传 = 独立不可再生资源轴**：`s.legend_used: bool`；`C_now` 加 `legend_consumption_cost`（仅本步打秘传时非 0），权重随回合数递减。【依据】P1（Q7）。
- **【决议】** 费用只保留**运行时 cost**，不在 `s` 区分 base cost。"减费来源是否可被对手破坏"另作 derived feature。【依据】P2+P3。

### 0.4 阶段 / pending_method / 决策点拓扑

- **【决议】** 被击倒后的 `chooseActive` 与开局/主动产生的 `chooseActive` **视为同一类决策点**（受限合法集中选最优出战）。**但两种行动后的行动权归属不同，需在 obs 中加以区分。**【玩家修正】补充了"行动权区分"要求。
- **【决议】** `selectCard` 归 `S_plan`（中间状态收益）为主，并**单列为 candidate family**（与 action / chooseActive 并列）。"信息释放代价"次要，第一版不单列。【依据】P1（Q2）。
- **【决议】** `switchHands`（mulligan）= **独立子策略，不进主 ranker**。【依据】P1+P4。【待议/区分】事件牌"草与智慧"有类似换牌效果，但战术语义不同（对局进行中按当前局面优化手牌），需单独处理，不与开局 mulligan 混同。

### 0.5 二段伤害管线

- **【决议】** safe/critical 二段结构是**引擎执行因果，不进 `T(s,a)`**；策略层只关心 `damage / kill / immune` 三态。【依据】P2。
- **【决议】** 斩杀判定改用"经 `modifyDamage3` 的最终值 ≥ HP"，直接调用引擎 `ActionPreviewer.modifyAndPreview`（`game.ts:1132`），**不重新实现启发式**。【依据】P3。

### 0.6 replaceAction

- **【决议】** `replaceAction` = `A(s)` 退化为单元素集（`|A(s)|=1`），ranker 自动退化，无需特殊代码路径。可加 `forced_action: bool` 供分析。【依据】P1+P2。
- **【决议】** 不引入"被强制度"维度——强制程度已由合法集 size 表达。【依据】P1。

## 一、定义层

### 1.1 状态语义

- **【决议】** 采用 **(c) 双层**：理论层用真值 `s=(公开,我方私有,对手私有)`；工程层 V/Q 都用 `policy_public` 视角的 belief_state 投影实现，二者一一对应。`debug_full` 仅训练时上界对照 / 对手建模数据增广，不进生产策略。【依据】P3。
- **【决议】** **不要求** `debug_full` 与 `policy_public` 两视角 V 一致（差值正是"完美信息红利"）；但要求两视角共用同一组 derived 特征定义（差异只在遮蔽字段）。【依据】P3。

### 1.2 Q_total 与 Q^π 桥接

- **【决议】** 风险归并规则（认可）：`R_role` → 全进 `γ·E[V(s')]`；`R_window` → 主进 `r(s,a)`、少量进 `γ·E[V(s')]`；`R_state` → 全进 `γ·E[V(s')]`。具体比例不重要（都进同一 V）。【依据】P5。
- **【决议】** 接受 `R_role` 语义切换："潜在坍缩"为正值项，`causeDefeated=true` 那一帧自动转为已兑现 `K_now`。每帧重算即自动转换，不维护历史。【依据】P1。

### 1.3 折扣系数 γ

- **【决议】** 第一版 **γ = 1**（终局二值 reward + 15 回合上限 → `V(s)=P(win|s)-P(loss|s)`）。【依据】P5（Q4）。
- **【决议】** `rounds_remaining = maxRoundsCount - roundNumber` 显式进 `policy_public`，不靠 γ 衰减表达时间压力。【依据】P3。

### 1.4 def 1 与 RL action contract

- **【玩家修正 / 待议】** 参考答案主张"骰子选择交启发式、不进 RL"，**用户不同意**：「必须留给后续行动特定颜色的骰子」决策**非常常见**。结论改为：**需先评估该维度的学习难度，再决定是否纳入学习**，不直接判死。重写时挂 TODO，不默认排除骰子选择。
- **【决议】** 调和的 `tuningTarget` 维度：当 `ChangeCardTuningTarget` 生效（多个可选 target）时**进 candidate 编码**；默认出战同色时省略。【依据】P1（Q6）。

## 二、价值层

### 2.1 D_now 拆项

- **【决议】** 直伤/穿透/分段**不细分**，`D_now` 保持聚合数值，差异由其他 obs 字段（目标 HP、后续反应）让模型自学。【依据】P1。
- **【决议】** 召唤物伤害：当回合触发 → `D_now`；未来回合 → `S_plan.summon_remaining_value`。**不另设 `D_summon_future`。**【依据】P1。【玩家补充】存在**回合内直接触发召唤物**的机制，当回合触发部分仍归 `D_now`。
- **【决议】** 反应链分两情形：**临时反应** → `D_now` 复合事件；**有意识设计的反应链**（雷鹤超导链、神宵融化等）→ `L_plan` 展开线。两者用 P5 多路径并行评估，不需分类器（靠 `L_plan.prerequisites` 细化，未触发则潜力自动小）。【依据】P1+P5。

### 2.2 K_now 拆分

- **【决议】** 采用 (a)：`K_now = K_kill + K_function_collapse + K_immune_break`，三者可同帧同时为正。【依据】P1。
- **【决议】** `K_kill` 衰减曲线：引导期 (b) deck-agnostic 代理（已用关键技能数 / 贡献兑现比例）优先、(a) deck-aware 模板兜底；**最终决策时由 S3 学习并接管**（P4：决策时 S3>S1>S2）。
- **【决议】** **2→1 比 3→2 更剧烈**：2→1 新增"无法切人让先手 / 无法规避伤害与反应"的不可恢复约束；3→2 仅"自由度下降"。`K_collapse_after_kill` 系数 2→1 ≥ 1.5× 于 3→2。【依据】用户原文。

### 2.3 T_now / T_plan 子指标（取代"节奏"原子概念）

- **【决议】** 可稳定计算（仅依赖己方/公开状态）：`dice_efficiency`、`action_advantage`、`tempo_pressure`、`window_alignment`、`priority_keep`。
- **【决议】** `forced_response_count` 需对手建模，第一版改写为"我方动作中**理论上**应迫使对手响应的次数"（effect family 标注 `reaction_enable / burst_enable` +1），不依赖对手实际行为。【依据】P3。
- **【决议】** 不补 `switch_value_delta`（已被单一 V 吸收，双计违反 P5）；需解释时用 candidate Q 值差，不进 obs。
- **【决议】** 子指标在 deck 间**共享同一组**，权重最终由 S3 学；引导期 GamePlan 模板给初值。不硬编码 archetype 权重表。【依据】P4。

### 2.4 S_plan 离散

- **【决议】** 固定四字段：`aura_setup_score` / `summon_remaining_value` / `support_remaining_value` / `position_alignment`。【依据】P1。
- **【决议】** "每次/每轮预期收益"第一版用全局平均（S2 引导），稳定后 S3 学 deck-aware 权重并接管。【依据】P4。
- **【决议】** 计数门槛触发支援（阿佩普绿洲守望者/草龙）**不单设 `setup_progress`**，并入 `support_remaining_value`，其"每次预期收益"为门槛函数（达阈值后跳变）。【依据】P1+P5。【玩家补充】草龙召唤物可通过**手牌/牌库弃置**召唤，也能在召唤物维度推进——建模时两条来路都要覆盖。

### 2.5 L_plan 展开线

- **【决议】** 形式化为三元组 `(prerequisites: 集合, completion: 0..1, payoff: 一次性大兑现)`。【依据】P5。
- **【决议】** **不引入 `setback_distance`**，但 `completion` 必须**双向**（可减少），每帧重算不维护历史，让 V 自学"哪些动作导致 completion 下降"。【依据】P1。
- **【决议】** 多条 L 线并存取 **`max`**（不取 `Σ`，避免"两条半成"误判"一条全成"）。【依据】P5。

## 三、风险层

### 3.1 功能的可计算定义

- **【决议】** 功能层级用**三个连续 score + max**（核心/战术/残余任务的 `E[Q_role|...]`），不离散分类。久岐忍刷新出战状态的"功能退降"由连续 score 表达。【依据】P5。
- **【决议】** 功能层级**随回合数 / 已兑现进度变化**（迪希雅 R2 vs R10）：score 计算函数接受 `current_round`、`cumulative_role_progress`，离散切换交 V 学。【依据】用户原文。
- **【决议】** "功能可兑现窗口"（core/tactical/residual_window）**只在 GamePlan 模板出现，不进 V 的 obs**；V 只看连续特征"距 core_window 末端还有几回合"。【依据】P4+P5。

### 3.2 风险时间尺度

- **【决议】** 数学化：`R_short(s,role)=P(role.alive=0 在下一次双方行动序列内)`、`R_mid(s,role)=P(role 无法在本回合完成预定职责)`。【依据】P1。
- **【决议】** `R_mid` 的"预定职责"：GamePlan 注入（S1）+ 角色层级兜底（S2）+ S3 学精细 deck-matchup 职责映射接管。【依据】P4。
- **【决议】** 跨回合风险用 `γ·E[V]` 自动覆盖，**不单建 `R_long`**。【依据】P5+P1。【待议】用户补充：玩家确实会对 2 回合后的极高风险预先行动（组件破坏：以极限之名/旧日鏖战；压血线/斩杀；限制行动：莱伊拉飞星、钟离天星），但大部分可归其他项——需后续详细检查与讨论是否完全可归并。

### 3.3 风险与反应增伤（严格按引擎加法）

- **【决议 / 已修正】** 删除乘法 `opponentReactionAmplifier`，改为加法 `opponentReactionBonus ∈ {+2,+1,0}`。威胁 = `damage_capacity + reaction_bonus`。`ai-improvement-plan-v3.md` §4.2 已据此重写 `computeCollapseDistance` / `estimateReactionBonus`。**全部相关错误已改。**【依据】P3 + 用户强制要求"严格按引擎层计算原则"。
- **【决议】** 第一版用阵营元素估计 + 固定加值表（S2 引导），后续 S3 由 matchup 历史反应频率/类型统计接管。【依据】P4。
- **【决议】** 威胁结构差异用 `damage_capacity_short / damage_capacity_long` 两连续值表达，**不区分"威胁类型"路由**。【依据】P5。

## 四、对手建模（minimax + 先验）

### 4.1 搜索深度与剪枝

- **【决议】** 搜索范围 = **(c) 双方各完整 1 回合（一整轮）**，之后用 `V(s_after_1_round)` 接管。覆盖"我方一回合 + 对方一回合"反击窗口，符合"看 ≥ 2 次行动"。【依据】P4 + 玩家级元规则。
- **【决议】** minimax 用于 candidate ranking（决策时刻），self-play 用于训练数据生成，两者不冲突。
- **【决议】** 剪枝先验 = (a)+(c)：先用 `Q_total` ranker（S3）取 top-k，再用 GamePlan 限定子集（S1）裁掉与主路径冲突候选。(b) effect-family 粒度太粗，不单用。【依据】P4。

### 4.2 隐藏信息与 minimax 协同

- **【决议】** 在线决策用对手手牌**统计期望分布**做 minimax（按概率加权各手牌世界单回合 minimax）；离线分析处理"信息效应"（威胁牌存在让对手不敢推进），不进在线评分。
- **【决议】** belief 更新：第一版 (a) 确定性硬证据（已打出/调和=减法）；第二版叠加 (b) 贝叶斯软更新，其概率参数由 S3 学，引导期不开。【依据】P4。

### 4.3 minimax 中"对手最优"

- **【决议】** (a) 同 evaluator 为主 + (c) archetype-aware bias 作 S3 数据稀疏时的初值；S3 充分后 bias 退化为可解释性提示。(b) 纯启发式偏弱，弃。【依据】P4。
- **【决议】** minimax 内部对手模型**不与 self-play 对手池一致**：内部假设"理想最优对手"（同 evaluator）保守估计，避免对弱对手过拟合。

## 五、阶段感知 / GamePlan

### 5.1 阶段判断与产出形式

- **【决议】** 引导期接受：阶段判断 = `f(组件就位向量, 关键技能可用性, 关键卡牌已抽到)`，原子跨卡组通用（S2），关键项由模板填（S1）。**长期目标**：S3 从原始 obs（手牌/装备/召唤物/能量）学隐含阶段，模板退化为可解释性 + 训练辅助标签。【依据】P4。
- **【决议】** GamePlan 模板产出 = (d) 三者结合，引导期优先级 LLM/手写（S1）> 离线学习（S3 候选挖掘）；S3 稳定后离线学习可生成 deck-matchup 精细模板覆盖。【依据】P4。
- **【决议】** **不输出离散阶段标签**；改为多个连续进度量 `setup_completion / execution_readiness / closing_pressure ∈ [0,1]`，让 V 处理三阶段并存。【依据】P5（推翻"phase_weight=1.0 离散标签"旧设）。

### 5.2 GamePlan 条件分支

- **【决议】** 触发器优先级 **a（对手阵容）> b（对手 R1 行动）> c（我方手牌）**（信息可达性）。引导期由模板定义分支（S1），S3 稳定后条件触发可由模型隐式学。【依据】P4。【玩家修正】c 可能在**起手换牌后**决定，**先手时 c 优先级会高于 b**。
- **【决议】** 路径切换次数 = **任意次，所有候选路径并行评估**，禁止"最多切 N 次"硬约束。"切换"非显式动作，是 V 内部权重移动，每帧允许胜出路径变化。【依据】P5。

## 六、数据采集 / 训练 / 评估

### 6.1 自对弈对称化

- **【决议】** 每 matchup 训练模型在 P0/P1 各打**等量**对局，benchmark 默认按 P0/P1 分层显示。【依据】P3。
- **【决议】** 需在 RL config 加"先后手交换 wrapper"（`currentTurn` 引擎硬编码从 0，wrapper 是唯一办法让训练模型一半时间作 sideB）。
- **【决议】** 镜像对局**混入**主训练数据（不单独 mode），obs 含"对手卡组指纹"让 V 自学同/异差异。【依据】P5。

### 6.2 reward shaping 优先级

- **【决议】** 第一版**只开 `burst_waste_penalty`**（S2 跨卡组通用、不依赖 deck 上下文）；`collapse_penalty / phase_alignment_bonus / key_char_protect_bonus` 依赖 deck-aware 信息，S3 未稳定不开。【依据】P4。
- **【决议】** 刷分透支用**事后回看修正**（terminal 倒推每步实际收益），不用当步即时削峰（削峰需局部分类，违反 P5）。
- **【决议】** 反应增伤事件**不进 shaping 白名单单列**：`r_damage` 已聚合（含 +2/+1），重复 shaping 违反 P1。

### 6.3 评估指标分层

- **【决议】** 补"先后手分层胜率"为副指标。【玩家修正】**不作为粗暴晋级硬约束**：受卡组强度限制，单个特定对局胜率可能就是上不去，阈值应放宽，不据特定对局极端胜率粗暴取舍（原"任一先后手<45%不晋级"过严，需软化）。
- **【决议】** 可解释性副指标用"错例 ranker top-1 vs ground truth gap"与"关键失误占比"两项；**不用** "Q_total 子项加性解释"（非线性 V 不保证可加分解）。【依据】P5。
