> 待统一交给 Claude 处理。

## 1. 爆发周期对齐的评分逻辑有误

文档将 `burstSyncScore`（两角色爆发周期对齐度）当作正面信号，`burstAlignment` 高的牌组得分更高。但实战中双角色同时攒 Q 是陷阱：

- **骰子黑洞**：两个 Q 合计 8-10 骰子，需提前空转蓄力
- **轮次浪费**：蓄力期间输出为零，送节奏
- **实际收益低**：爆发伤害可被规避（切人/护盾/治疗），综合 DPT 不如持续输出

好的队伍往往是**爆发周期错开**（A 爆发时 B 蓄力），而非对齐。

**当前设计能部分捕捉**：`canDualOutputInOneRound: false`、高 `minDiceForFullRotation` 等字段会标出问题。**但评分权重方向反了**——`burstSyncScore` 高不应加分，应减分或作为需模拟验证的标记。

**建议**：重新定义 `burstAlignment` 的语义，改为"爆发周期交错度"（stagger），高分 = 周期互补而非对齐。

## 2. 同一技能在不同回合的收益差异问题

角色同一技能在不同游戏阶段的实际收益差异很大。例如：
- 迪卢克 E：前期挂火打反应 vs 后期裸火直伤，收益差距明显
- 优菈普攻：前几层只做铺垫，光降之剑层满才爆发
- 闲云 E：风翎层数不同时伤害完全不同

当前 `SkillProfile` 只记录静态数值（固定伤害值），无法反映这种**状态依赖的收益曲线**。需要在静态分析阶段给出某种初步的回合收益分布估计。

### 初步评估思路：引入「技能阶段收益模型」

将一局对局粗分为 3 个阶段，为每个技能在每个阶段给一个粗估值：

```typescript
interface SkillPhaseValue {
  skillId: number;

  // 三阶段粗估值（相对于该技能最大可能收益的百分比）
  earlyGame: number;   // 回合 1-3：启动期
  midGame: number;     // 回合 4-6：运转期
  lateGame: number;    // 回合 7+：决胜期

  // 收益随回合的变化趋势
  trend: "ramp_up" | "stable" | "decay" | "spike_then_decay";

  // 收益高度依赖的前置条件（用于标记哪些阶段估值不可靠）
  preconditions: string[];
}
```

#### 估值方法（启发式，不需要模拟）

**1. 按技能类型分基准曲线**

| 技能类型 | 典型曲线 | 依据 |
|---------|---------|------|
| 挂元素/施放召唤物 | `ramp_up` | 召唤物存在期间每回合持续产出，越早放收益越高 |
| 增伤 buff | `spike_then_decay` | 后续技能吃满 buff 后，buff 本身不再产生额外收益 |
| 积层数技能（优菈普攻） | `ramp_up` | 前几层收益低，满层后爆发 |
| 固定伤害技能（迪卢克 E） | `stable`（反应期）/ `decay`（无反应时） | 依赖后台元素附着状态 |
| 治疗/护盾 | `earlyGame` 高 / `lateGame` 高（取决于是预防还是应急） | 中期通常溢出 |

**2. 按队伍元素覆盖修正**

- 前期（1-3回合）：元素反应尚未稳定，挂元素技能收益 > 直伤技能
- 中期：反应稳定，直伤+反应综合收益最高
- 后期：对手可能已无护盾/治疗，直伤价值上升

修正系数可以简单用 `hasReactionPartner` 和 `elementCoverage` 字段推导。

**3. 机会成本估算**

每个阶段能执行的行动数有限（8骰/回合），技能的"真实收益"应减去该阶段不使用最优技能的机会成本。简化做法：

```
阶段真实收益 ≈ 阶段粗估值 × (1 - 该阶段平均机会成本)
```

其中机会成本可以用该角色在该阶段所有可选技能中最高收益技能的值来近似。

**4. 标记不确定性**

关键：对于条件依赖强的技能（需要队友先挂元素、需要特定状态），`preconditions` 列表应明确标注，告诉下游 plan-v2 这些阶段的估值不可靠，需要模拟校准。

#### 与现有方案的关系

这个模型直接扩展 `CharacterOutputProfile`：

- `rhythm.rawDamagePerCombatAction` 改为 `rhythm.phaseDamage: [early, mid, late]`
- 新增 `SkillProfile.phaseValues`
- `complexity` 中新增 `hasPhaseDependentValue: boolean`

#### 精度预期

这个模型仍然是粗估——它捕捉的是"方向性"而非精确值：
- 能区分「越早打越好」和「攒到后期爆发」两类技能
- 能标出「哪些阶段估值不可靠」交给模拟
- 不能精确量化具体差值

这正是静态分析的合理边界——**能指出问题在哪里，把精确计算留给模拟**。
