# Concise and Precise Context Compression for Tool-Using Language Models

- **arXiv ID**: [2407.02043](https://arxiv.org/abs/2407.02043)
- **Authors**: (2024 paper)
- **Date**: 2024-07-02
- **Venue**: arXiv preprint (cs.CL)
- **Citations**: Moderate
- **Relevance Score**: ⭐⭐⭐ (3/5 — MCP 工具文档的专用压缩)

## Summary

工具使用型语言模型每次调用工具时都需要输入冗长的文档（描述、参数、返回值），占用输入窗口并拖慢解码。现有 soft context compression 在压缩工具文档时存在关键信息丢失（工具名/参数名错误）和无法灵活调整压缩长度的问题。提出两个策略：(1) **Selective Compression**：关键信息（工具名、参数名）保留为 raw text token，防止丢失；(2) **Block Compression**：将文档分块，用固定长度压缩模型实现可变长度输出。两个策略结合，实现简洁且精确的工具文档压缩。

## Key Contributions

- **选择性压缩**：工具名/参数名硬保留 raw text（不容错），描述文字做软压缩
- **分块压缩**：突破固定长度压缩的限制，对不同长度的工具文档都可以输出合适长度
- 专门针对 tool-using LLM 场景（与我们 MCP 架构高度相关）

## Connection to Our Work

- **MCP 工具 schema 压缩**：`StandaloneMcpToolHandler` 暴露的 8+ 个工具各自有 schema 描述（参数名、类型、说明）。Selective Compression 可以直接应用——工具名和参数名保留 raw text，冗长的 description 做压缩。
- **与 MemTool 互补**：MemTool 决定「哪些工具保留在 context 中」（高层面），这篇决定「保留的工具描述怎么压缩」（细节面）。两者可以组合使用。
- **低优先级落地**：相比 MEMO（记忆增强）和 SUPO（压缩策略优化），工具文档压缩是锦上添花——先做架构级的 context 管理，再做字节级的工具文档压缩。

## Critical Assessment

**Strengths**: 针对 tool-using 场景的专用方案；Selective Compression 的 raw-text 保留设计实用。  
**Weaknesses**: 工具文档压缩的收益是线性的（省 N 个 token），不像 MEMO（记忆增强）是结构性收益；GI TCG 的工具 schema 本身不长，压缩收益可能有限。  
**Reproducibility**: 方法清晰。
