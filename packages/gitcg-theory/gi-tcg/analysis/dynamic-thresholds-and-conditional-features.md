# 阈值的动态性与角色特征的不刚性

> 承接 strong-coupling-and-deckbuilding.md，继续深入。

## 阈值不是固定的，甚至"没有发生的事"也在改变阈值

### 1. 阈值的动态性

前一节提出用"阈值"替代折算——不问值多少，问够不够。但这立即遇到问题：**阈值本身在对局中持续变化**。

例子：
- 回合 1：对手打得保守，你的"场面压力够不够"阈值较低——挂个召唤物就算达标
- 回合 4：对手已经拍了两张增伤牌，你的阈值飙升——必须在这一回合造成可观的伤害，否则节奏彻底丢失
- 回合 7：对手只剩 1 血的角色，阈值又变了——只需要 1 点伤害就能斩杀

阈值不是牌组属性，不是角色属性，它是**博弈状态的函数**。你无法在对局之外说"这张牌需要达到 X 伤害才算合格"。

### 2. 未生效数值的信息效应

更微妙的是：**一张牌即使没有被使用，它的存在本身就在影响博弈**。以下例子受LLM的幻觉影响不作为实际卡牌效果参考。

- 你手牌里有一张「鹤归之时」→ 对手知道你随时可能打出，行为上会更谨慎（比如不会轻易用完骰子）
- 你的牌组里带了「送你一程」（302001）→ 对手在角色 1 血时会改变行为（可能提前切人），即使你整局都没抽到这张牌
- 你装备了「饰铁之花」→ 对手知道你角色倒下时有额外收益，可能选择不打倒你而是打残

这些影响是**不可观测的**——你无法在赛后回放中看到"对手因为这张牌而改变的那次决策"。但它真实地改变了对局的概率分布。

**结论**：我们讨论的"收益"不只是"这张牌打出后的效果"，还包括"这张牌在手/在牌组中对对手决策空间的压缩"。后者甚至可能比前者更大。

### 3. 这是个概率分布问题，不是数值问题

既然阈值动态变化、未生效数值也有信息效应，那么任何单点数值评估都是无意义的。我们真正需要的是：

```
P(这张牌的净收益 > X) = ?
```

即：这张牌的净收益超过某个阈值的概率是多少。

这不是一个数，是一条**分布曲线**。

```typescript
interface ProbabilisticValue {
  distribution: {
    low: number;      // 最差情况下的收益（对手完美应对）
    median: number;   // 中位数（对手随机应对）
    high: number;     // 最好情况下的收益（对手犯错）
    p50: number;      // 50% 对局中的收益
    p90: number;      // 90% 对局中的收益
  };
  // 这个分布的形状
  shape: "narrow_peak" | "wide_uniform" | "bimodal" | "skewed_high" | "skewed_low";
  // 分布形状的含义
  shapeMeaning: string;
}
```

- **窄峰分布**（narrow_peak）：这张牌在各种对局中表现稳定 → 适合作为构筑核心
- **双峰分布**（bimodal）：这张牌要么极强要么极弱 → 适合作为针对卡，取决于 meta
- **宽均匀分布**（wide_uniform）：这张牌什么场景都凑合 → 适合作为灵活填充

这比"这张牌值 7 分"诚实得多，且保留了决策所需的信息。

### 4. plan-v2 的数值在这个框架下的位置

plan-v2 可以通过模拟搜索计算出具体的行动序列收益。但这个收益是**条件性的**——给定特定的 GameState 和对手策略模型后的最优解。

问题在于：
- 模拟结果是对**一个具体局面**的精确回答
- 构筑讨论需要的是对**所有可能局面**的概率性回答
- 两者之间有一个"从具体到一般"的归纳鸿沟

plan-v2 能告诉你："在这个局面下，打出这张牌的期望收益是 4.7"。但不能告诉你："在所有可能的局面中，这张牌的收益分布是什么"。

后者需要**跨局面聚合**——对大量模拟结果做统计。这是 plan-v2 当前的架构设计之外的东西，但并非不可扩展。

## 角色选择的竞争困境：没有刚性的"特征发力向量"

### 1. 为什么角色选择仍然需要比较

构筑论虽然在卡牌层面失效，但角色选择层面的问题依然存在：当你需要在"香菱"和"班尼特"之间选一个火系辅助时，你必须做出选择。你不能两个都带（三个角色位有限），也不能说"它们扮演不同角色所以不需要比较"——因为它们竞争的是**同一个位置**。

### 2. "特征发力向量"为什么不刚性

前一节（三角色坍缩）已经说明：角色在不同队伍约束下的最优行为完全不同。这意味着：

**角色不存在一个不依赖队伍的、固定的"特征向量"。**

类比：
- 构筑论想做的是：测量每个角色的"固有属性"（如长度、重量），然后匹配
- 实际情况是：角色的"属性"取决于它被放在什么环境里——这更像是量子力学中的**测量问题**，观测方式决定了结果

香菱在"迪卢克+行秋+香菱"中的特征：
```
→ 后台挂火 + 旋火轮持续输出
→ 发力方向：持续性后台伤害
→ 关键指标：DoT per round
```

香菱在"班尼特+香菱+某后台"中的特征：
```
→ 前台输出（因为班尼特提供了足够的增伤和生存）
→ 发力方向：E 技能直伤 + 旋火轮
→ 关键指标：burst damage + DoT
```

两个"香菱"的发力向量完全不同。你无法提取出一个"香菱的刚性特征"来和班尼特比较。

### 3. 那人类是怎么做选择的？

人类玩家在选角色时，实际上做的是**情境模拟**：

"如果我想打蒸发队，那主 C 需要火系前台……迪卢克还是可莉？迪卢克有长时间前台但爆发低，可莉爆发高但充能慢……我的另一个位置是行秋打后台挂水……行秋需要充能时间所以对局会比较长……迪卢克在长对局中更稳……选迪卢克。"

这不是在比较"迪卢克 vs 可莉"的绝对强度，而是在**构造一个具体的对局叙事**，然后看哪个角色在这个叙事中更合适。

但这个叙事本身是脆弱的——换一个对手，整个推理链可能翻转。

### 4. 对 AI 系统的启示：特征应该是条件性的

如果角色不存在刚性特征向量，那么 AI 系统应该输出的是**条件性特征**：

```typescript
interface ConditionalCharacterProfile {
  characterId: number;

  // 不是单一特征向量，而是一组条件→特征映射
  modes: {
    condition: string;       // "作为后台输出者" / "作为前台主C" / "与水系配合"
    featureVector: number[];  // 该条件下的发力方向
    synergyWith: number[];    // 在该模式下与哪些角色配合好
    antiSynergyWith: number[];// 在该模式下与哪些角色冲突
  }[];
}
```

这承认了一个事实：**角色的"本质"是多样的**，取决于它被放在什么位置。这不完美，但比强制提取单一向量诚实。

## 寻求秩序：为什么我们需要更强的工具

### 1. 人类的天性

面对复杂系统，人类天然会试图：
1. **寻找模式**——"这套牌组的共同点是什么？"
2. **建立分类**——"攻击型 vs 控制型 vs 节奏型"
3. **排序比较**——"哪个角色更强？"
4. **因果归因**——"我输了是因为没有带 X 牌"

这些认知工具在简单系统中有效。在七圣召唤这种强耦合系统中，它们**系统性失效**——不是因为人类不够聪明，而是因为系统本身的结构使得这些工具的前提假设不成立。

### 2. 社区讨论的现状

当前社区"嘴炮"的困境：
- **A 说**："这张牌很强，我带了之后胜率提升了" → 样本偏差，对手水平不同
- **B 说**："不对，这张牌只在对 X 牌组时有用" → 正确但不可操作——你不知道对手打什么
- **C 说**："你们都在讨论单卡，应该看牌组整体" → 方向对但无法具体讨论——"牌组整体"怎么量化？
- **D 说**："实践出真知，去打 100 把就知道了" → 对个人有效但无法传播经验

大家说的都对，但无法汇聚成可积累的知识。

### 3. 我们需要什么样的工具

我们需要能把以下内容**形式化并可视化**的工具：

**a) 条件性陈述的可视化**

不问"X 强不强"，而是让用户输入条件，工具回答"在这些条件下，X 的表现分布是什么"。例如：

```
输入：对手是快攻牌组 / 我方角色还剩 2 个 / 当前回合 5
输出：[卡牌列表]，每张卡显示 在该条件下的收益分布曲线]
```

**b) 角色模式探索器**

给定一个角色，展示它在不同队伍配置下的"发力模式"。不是一个向量，而是一组**情境化的行为描述**：

```
角色：香菱
模式 1（与火C配合）：后台持续伤害，发力期回合 2-6
模式 2（与水系反应配合）：蒸发触发器，发力期取决于对手元素附着
模式 3（单核输出）：前排输出 + 旋火轮，但生存能力差
```

**c) 非传递性检测器**

检测牌组间的克制关系链（A 克 B 克 C 克 A），将"谁最强"的问题转化为"克制的方向是什么"。

**d) 信息效应评估器**

评估某张牌即使不打出，作为"威胁"存在的价值——通过模拟"有这张牌"vs"没有这张牌"时对手行为的差异。

### 4. 工具的定位：不是替代人类判断，而是扩展可讨论的维度

这些工具不追求给出"最终答案"（因为不存在），而是：

1. **把隐性知识显性化**——让"感觉这张牌有用"变成"这张牌在 60% 的模拟对局中收益 > 阈值"
2. **把线性讨论升级为系统讨论**——从"X vs Y 哪个强"变成"在什么条件下 X > Y"
3. **让社区的知识可积累**——每个人的测试结果可以汇入分布模型，而不是互相矛盾的轶事证据

这本质上是在为社区"嘴炮"提供一个**共享的数学语言**。大家不需要同意"哪张牌最强"，但可以同意"这张牌在以下条件下的期望收益分布是这样的"——这是可积累的、可检验的、可争论的。

## 开放问题

1. **人类认知限制**：即使我们有了概率分布、条件特征、帕累托前沿这些更诚实的工具，人类的大脑真的能有效地使用这些高维信息来做决策吗？还是说我们最终仍然需要一个压缩函数，把高维信息压回人类可理解的叙事？

2. **"足够好"的近似**：也许问题不在于找到"正确"的评估框架，而在于找到一个"足够好"的近似——允许错误，但方向大致对。什么样的近似是"足够好"的？

3. **工具的形式**：这些工具应该是 AI 对话式的（"帮我分析一下"）还是交互式可视化（拖拽参数看分布）？不同形式适合不同的讨论场景（研究 vs 社区争论）。

4. **与现有体系的桥接**：社区已经在用"标准模型+折算"这套语言讨论了。是否有办法在现有语言中渐进引入新概念，而不是要求全盘推翻？（类比：相对论没有推翻牛顿力学，而是在更高速度/精度下扩展了它。）
