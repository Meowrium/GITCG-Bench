## Summary

LLM agent 在多轮交互中需要反复使用工具/MCP server，但固定 context window 限制了有效性。MemTool 是短期记忆框架，让 LLM agent 在多轮对话中动态管理工具或 MCP server context。三种模式：(1) Autonomous Agent Mode（全自主管理），(2) Workflow Mode（确定性控制），(3) Hybrid Mode（混合）。在 ScaleMCP benchmark 上评估 13+ LLM，跑 100+ 连续用户交互。reasoning LLM 在 Autonomous Mode 达到 90-94% 工具移除率（3 窗口平均），中型模型只有 0-60%。

## Key Contributions

- **三层记忆管理模式**：Autonomous（自主）/ Workflow（确定性）/ Hybrid（混合），适配不同 LLM 能力
- **工具移除率 vs 任务完成率的 tradeoff**：reasoning LLM 可以用 90%+ 移除率保持任务完成率；弱模型同一移除率下任务完成率骤降
- **ScaleMCP benchmark**：100+ 连续交互的 MCP 工具管理评测

## Connection to Our Work

- **MCP 工具 schema 占 token**：当前 `MCP_TOOL_EXPOSURE_MODE=fragmented-decision` 虽然隐藏了动作工具，但仍有 8+ 个可见工具（`get_turn_digest_v1`, `submit_decision_fragment_v1` 等），每个工具的 schema 描述占 token。MemTool 的思路是「动态决定哪些工具描述保留在 context 中」。
- **对 GI TCG 的启示**：对局的不同阶段需要不同工具——开局需要 `create_opening_plan_v2`、中期不需要；回合中需要 `get_turn_digest_v1`、对手回合不需要。可以用 hybrid mode：Workflow mode 定义哪些工具在哪个阶段可见，Autonomous mode 让 LLM 在阶段内动态决定。
- **MCP server 层实现**：可以在 `StandaloneMcpToolHandler` 增加 `exposure_dynamic` 模式——不是 fragmented/direct-action 的硬切换，而是基于游戏阶段的工具裁剪。

## Critical Assessment

**Strengths**: 直接针对 MCP 场景；91-94% 移除率且不丢任务完成率的实证；三种模式覆盖不同 LLM 能力层次。  
**Weaknesses**: 100 轮交互对 GI TCG 对局（通常 10-20 回合）的 context 压力差异大；中型模型表现差可能影响我们的模型选择。  
**Reproducibility**: 高——框架设计清晰，可以直接在 MCP server 层实现。
