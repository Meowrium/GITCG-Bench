# GI-TCG 角色/卡牌配合相性的精确度量

> 与对手无关的内部结构度量。回答"为什么 莫娜+雷神 比 莫娜+一斗 配合更好"这类问题，不必依赖具体对局数据。

---

## 核心定义

角色配合相性 = 卡组内部元素间通过**反应机制、技能链、职能互补、行动牌增强**产生的协同效率。**完全由卡组自身定义**，不需要知道对手是谁。

区别："我方卡组 vs 对手卡组"的优劣势是对阵相性（matchup delta），见 `action-rationality-constraints.md` 第④节。

---

## 四维度度量框架

### ① 元素反应兼容性 (Reaction Potential)

**原理**：两元素的反应类型和伤害系数是规则定义的，与出牌顺序和对手无关。

```
R(deck) = Σ_ij p(i,j) × v(reaction(aura_i, aura_j))
```

- `p(i,j)`: 角色 i 和 j 同时存活且可行动的概率（按部署顺序估算）
- `v(reaction)`: 反应的价值系数，**改用引擎实值**（`increaseDamageByReaction` 固定加值，见 `framework-deepening-questions-for-expert.md` §0.2 / `framework-resolved-decisions.md` §7.2）。直接增伤部分按引擎加值取，控制/附带收益作为附加权重显式说明，避免与对局内 `D_now` 数值脱节：
  - 蒸发/融化（火+水/冰+火）：引擎 **+2** → `v = 2`
  - 超载（火+雷）：引擎 **+2** → `v = 2`
  - 超导（冰+雷）：引擎 **+1**（穿透 1 + 后续物理/冰伤增益）→ `v = 1`
  - 感电（水+雷）：引擎 **+1** → `v = 1`
  - 冻结（水+冰）：引擎 **+1**，附"当回合跳过行动"控制 → `v = 1`（+ 控制附加权重，见职能互补维度）
  - 结晶（岩+火/水/雷/冰）：引擎 **+1**，附生成护盾 → `v = 1`
  - 燃烧 / 绽放 / 激化 / 月相绽放：引擎 **+1** → `v = 1`
  - 扩散（风+火/水/雷/冰）：引擎直接增伤 **+0**，附 AoE 附带伤害 → `v = 0`（AoE 收益另计，不入直接增伤项）
  - 无反应或同元素 → 0

> 说明：控制（冻结/超载击退）、AoE（扩散）、产盾（结晶）等**非直接增伤收益**不再折算进 `v(reaction)` 的增伤数值，而是分流到「职能互补」维度按其策略价值单独加权，以保证 `v(reaction)` 与引擎实际增伤一一对应。

**计算示例（雷鹤 = 申鹤/雷电将军/重云）**：
> 数据源: `packages/data/src/characters/cryo/shenhe.ts` (ID=1107), `electro/raiden_shogun.ts` (ID=1407), `cryo/chongyun.ts` (ID=1104)
- 冰+雷 = 超导 → v=1（引擎 +1）
- 双冰同元素无反应
- **反应兼容性 R = 1 × p(冰存活) ≈ 1**

**反例（三元素混色 = 神宵 = 宵宫/神里绫华 + 第三角色）**：
> 数据源: `packages/data/src/characters/pyro/yoimiya.ts` (ID=1305), `cryo/kamisato_ayaka.ts` (ID=1105)
- 火+冰 = 融化 → v=2（引擎 +2）
- 但三元素稀释了匹配骰子概率
- **反应兼容性需乘骰子折扣因子**

### ② 技能链配合效率 (Skill Chain Synergy)

**原理**：角色 A 的技能效果能否被角色 B 利用，形成**自动化协同**，而非各自为战。

```
S(deck) = Σ_k w(actionA_k → beneficiary_in_actionB)
```

关键链模式（无需对手参与）：

| 模式 | 例子 | 权重 |
|------|------|:---:|
| E 召唤 → 后续角色普攻触发反应 | 莫娜 E 虚影(挂水, ID=12032) → 雷神普攻(感电) | 0.3 |
| Q 生成 combat status → 队友触发 | 宵宫 Q 琉金火光(ID=13053) → 神里普攻(融化) | 0.4 |
| 天赋卡打出即触发对应技能 | 宵宫天赋(长野原龙势流星群, ID=213051, 1火骰)打出立即使用焰硝庭火舞 | 0.3 |
| 召唤物提供屏障+回合末伤害 | 一斗 E 阿丑(ushis, ID=16052, 3岩骰) → 挡1伤+挂乱神之怪力 | 0.25 |
| E 挂元素 → 切人 → E 触发反应 | 迪希雅 E 熔铁流狱(挂火, ID=13092) → 一斗普攻/技能(结晶反应) | 0.2 |
| 支援牌减费/补骰 | 卯师傅(ID=322005, 1同色骰) → 打料理牌时生成随机元素骰+抽料理 | 0.15 |

**计算示例（莫优 = 莫娜/流浪者/优菈）**：
- 莫娜 E(虚影挂水) → 流浪者普攻(感电) = 0.3
- 莫娜 被动速切 → 流浪者/优菈 = 0.2
- **技能链 S = 0.5**（中等协同）

**计算示例（红牛 = 一斗/迪希雅/诺艾尔）**：
> 数据源: `packages/data/src/characters/geo/arataki_itto.ts` (ID=1605), `pyro/dehya.ts` (ID=1309), `geo/noelle.ts` (ID=1602)
- 一斗 E 阿丑(ID=16052, 3岩骰) → 挡1伤+回合末岩伤+挂乱神之怪力 = 0.3
- 迪希雅 E 熔铁流狱(挂火, ID=13092, 3火骰) → 一斗普攻/技能(结晶) = 0.2
- 一斗 Q 怒目鬼王(ID=16053, 3岩+3能) → 普攻转岩伤+增伤 = 0.3
- **技能链 S = 0.8**（内部循环完成度高）

### ③ 角色职能互补度 (Role Completeness)

**原理**：卡组的 3 个角色应覆盖不同的博弈职能。职能重叠 = 浪费角色槽。

```
角色职能向量 v = [DPS能, 元素附着能, 承伤能, 辅助能(回复+过牌+骰子)]
```

- **DPS能**：技能伤害期望 / 回合
- **元素附着能**：E 技能的附着频率和持续时间
- **承伤能**：HP + 自回复 + 减伤被动
- **辅助能**：过牌数 + 骰子生成 + 团队增益 Q

```
互补度 C(deck) = 1 - ||Σ角色v_i - 理想分布|| / max_dist
```

理想分布取决于 archertype（速攻 偏 DPS+附着，控制 偏承伤+辅助）。

**计算示例（水凝 = 心海/行秋/芭芭拉）**：
- 三辅助 → DPS能严重不足
- 互补度 C 低，但辅助能极高 → 适合拖长局
- **这不是"低相性"，而是"极度偏科"** —— 度量本身揭示设计意图

### ④ 行动牌增强匹配度 (Card-Character Affinity)

**原理**：评估每张行动牌是否放大了角色的核心能力，而非泛用填充。

```
A(deck) = Σ_card w_match(card, best_char) × penalty(deploy_window)
```

匹配类型：

| 匹配 | 检测方式 | 权重 | 数据源 |
|------|---------|:---:|------|
| 天赋卡在卡组中 | talentCardId ∈ deck.cardIds | 0.5 | 各角色文件末尾 `card(2XX)` 定义 |
| 食品+卯师傅联动 | "食品" tag + 卯师傅在场(1同色骰, ID=322005) | 0.3 | `cards/support/ally.ts` |
| 武器与角色元素匹配 | 武器元素 == 角色元素 | 0.2 | |
| 圣遗物与角色 HP/充能匹配 | artifact.condition 匹配 char.base | 0.15 | |
| 共鸣牌与双元素匹配 | 双同元素 → 共鸣有效 | 0.25 | |
| 泛用牌(送你一程/星天之兆) | 无特定匹配 | 0.05 | |

**penalty(deploy_window)**：牌不在最佳部署窗口时，匹配度打折扣（R4+ 打立本匹配度 ×0.3）。

## 综合相性分数

```
Synergy(deck) = α·R + β·S + γ·C + δ·A

默认权重: α=0.25, β=0.35, γ=0.25, δ=0.15
(技能链最重要，因为它是卡组的"引擎"；元素反应是基础；职能互补保下限；牌增强是锦上添花)
```

### 示例对照

| 卡组 | R(反应) | S(技能链) | C(互补) | A(牌增强) | 综合 | 解释 |
|------|:---:|:---:|:---:|:---:|:---:|------|
| **雷鹤** | 1.5 | 0.6 | 0.7 | 0.3 | 0.83 | 申鹤+雷神超导引擎（申鹤ID=1107, 雷神ID=1407, 重云ID=1104）|
| **莫优** | 1.2 | 0.5 | 0.6 | 0.25 | 0.68 | 莫娜被动速切+感电，缺爆发 |
| **红牛** | 0.6 | 0.8 | 0.8 | 0.4 | **0.71** | 一斗E→Q自循环+迪希雅E挂火→结晶+护盾互补（一斗ID=1605, 迪希雅ID=1309, 诺艾尔ID=1602）|
| **水凝** | 0.3 | 0.3 | 0.2(DPS) | 0.2 | 0.26 | 极度偏辅助，靠拖长局取胜 |
| **水八** | 0.8 | 0.4 | 0.5 | 0.3 | 0.53 | 感电体系（卡组组成待源码验证）|
| **水债** | 0.8 | 0.45 | 0.55 | 0.3 | 0.55 | 感电+召唤体系（卡组组成待源码验证）|
| **神宵** | 1.2 | 0.35 | 0.5 | 0.2 | 0.58 | 宵宫Q→神里融化的爆发潜力（宵宫ID=1305, 神里ID=1105）；第三角色骰子匹配差 |
| **雷狼** | 0.9 | 0.5 | 0.55 | 0.25 | 0.59 | 超导+AOE（卡组组成待源码验证）|

>
> ⚠️ **R 列待重算**：上表 `R(反应)` 与 `综合` 列基于**旧版估值权重**（超导 1.5 / 蒸发融化 2.0 等）算出。`v(reaction)` 已按 `framework-resolved-decisions.md` §7.2【玩家修正】改用引擎实值（超导 +1、蒸发/融化/超载 +2、其余 +1、扩散 +0），控制/AoE/护盾收益改入「职能互补」维度。本表 R 与综合需据新口径重新计算后替换，当前数值仅供结构参考。

## 与七大约束的关系

| 约束 | 相性如何关联 |
|------|-------------|
| ① 骰子预算 | 元素兼容性 R 直接影响骰子匹配概率 |
| ② 承诺不可逆 | 技能链 S 评估了"打了E之后能否被后续角色利用" |
| ④ 对抗响应 | 相性高=即使被对手反击，内部协同仍能运转 |
| ⑤ 斩杀阈值 | 互补度 C 中的 DPS 能量化了斩杀能力 |
| ⑥ 战略折现 | 牌增强匹配度 A 中的 deploy_window 编码了最佳时机 |

相性度量弥补了七大约束中缺失的**静态结构分析**。约束②④⑤⑥回答的是"在对局中这个动作对不对"，而相性回答的是"这套卡组本身设计得好不好"。
