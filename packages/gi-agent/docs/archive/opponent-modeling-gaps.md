# 对手行为建模 — 知识缺口与人工填写清单

> **⚠️ 状态：部分过时** — 10 缺口清单结构仍有效，但具体填写内容可能已过时。待更新。 最后审阅：2026-05-16. 见 [INDEX.md](INDEX.md)

> 当前 AI (GBDT + 时序特征) 能做的：给定静止棋盘，评估每步的直接收益。
> 当前 AI **不能**做的：预测对手会怎么回应、对手的战略意图、多步博弈树的剪枝。
> 
> **一句话问题：打木桩只需要总伤，但七圣召唤是博弈——没有对手模型，时序推理无法成立。**

---

## 为什么对手模型是时序推理的前提

从框架 V2 的对局分析，所有时序推理都依赖对手行为假设：

```
T1 风险评估: "对方会切走避扩散吗？" → 观察对方行为 → 判断是否继续原计划
T2 扩散时机: "对方如果切宵宫挡刀，我扩散谁？" → 对方实际行为决定伤害分配
T3 冻结锁: "对方能否解冻？有没有切人空间？" → 对方行动决定最优策略
```

**即使是最简单的 Phase 1 时序特征（开局/中局/斩杀），对手的实际节奏才能定义真正的阶段转换。**

## 填写后如何使用

这篇文档填完后，可以分为三层落地：

### 短期（可直接写入代码）
- **对手 T1 行为模板 (§1)** → 写入 `opponent-model.ts` 的 `OpponentPrior.byDeck()` 初始化
- **切人触发条件 (§2)** → 作为 `GiMlPolicy` 的 `opponentAdjustment` 信号
- **对手斩杀线 (§6)** → 作为 `HeuristicScorer` 的 `oppWindowPenalty` 动态计算

### 中期（需要训练）
- **技能选择逻辑 (§3)** → 从 self-play replay 提取模式，训练对手行为分类器
- **资源推断 (§5)** → 作为 concept 输入 `SlotLinearRanker`

### 长期（需要搜索/博弈树）
- **反制行为 (§4)** → 需要 minimax 搜索中模拟对手的对抗动作
- **阶段转换触发器 (§7)** → 需要 MCTS 或 AlphaBeta 混合搜索才能精确建模
